# Native host batch7 connection draft

The [batch7 connection report](../../docs/NATIVE_HOST_BATCH7_CONNECTION_20261114.md) follows the [[native-host-batch6-capture-contract-2026-11-14|blocked batch6 source candidate]]. It pins A5 and A7 source layers over A4 without editing operational `libtorch/`. A5 records the original warm/cold predicates and unexpanded controls; A7 retains seven outer-selected state/fall tensors and separates ProgB BG reset from transport candidates. These source sites are not a runtime census or conservative interface flux.

The draft FD consumer rejects swapped endpoint IDs and call sequences against canonical 624-word inputs. An opt-in ABI reader copies v2 records before the same-call context closes, and a v3 bridge joins 45 ordered caller-supplied capture assets to the pinned plan. Complete relabeling plus rehashing remains self-attested, so FD projection stays `UNRESOLVED` or `UNSUPPORTED` for mixed one-step phases and never becomes eligible. A phase-selector draft checks reviewed structural identities but does not establish full coverage.

An isolated A5+A7 macOS source build passed four non-KDM research CTests and retained 28 exports. The changed DSO has **not** executed the A4 synthetic parity fixture, a six-forward value matrix, a graph derivative test, or the native 45-input batch. The value-only parity CTest is built but marked `CONTAINMENT_PENDING` for the A7 CI candidate. External watchdog/witness behavior, loaded DSO provenance and complete call journals remain prerequisites for a synthetic graph run. The scientific and physical-unit statuses remain `INCONCLUSIVE`.

The phase validator now enforces exact integer ranges and the source-proven microphysics relation `one_step_call == outer + 1`; this remains structural screening. The A7 source CI candidate also preserves a bounded ON build bundle (DSO, unrun test executable, final snapshot, earlier asset hashes, flags, JUnit and receipt) and a separate verifier compares it to independently supplied source, binary and toolchain pins. The bundle can establish reusable build-asset consistency, not model execution or derivative correctness. The later final-head CI preserved Linux and macOS bundles and their files matched the manifests; this is build-asset consistency, while actual binary reuse and model execution remain unverified.

A local smoke of the packaging/verification code over the already built macOS A7 files produced a 1,950,178-byte bundle and returned `VERIFIED_BUILD_ASSET_ONLY`. Its receipt was manually assembled from observed files, so this test does not authenticate a hosted producer or a model execution.
