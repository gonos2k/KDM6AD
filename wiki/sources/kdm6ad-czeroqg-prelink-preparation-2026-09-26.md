# S10 exact-zero graupel quotient guard prelink preparation

The new [S10 prelink plan](../../harness/evidence/s10_czeroqg_prelink_plan_2026-09-26.json) supersedes the earlier native plan's stale `current_c_guard_overlay: null` fields. Fresh C-arm overlays were generated from the private host pins and their macro-off forms match the corresponding B midpoint sources byte-for-byte: mp37 C `d1c16f3a…b30467a3` / B `70f101d9…bd84a935`; mp237 C `f32cc1c7…b76174f5` / B `6be24e8c…1c7eca`.

Prelink preparation identified copied build residue in the disposable host. Historical logs, the prior `configure.wrf`, the shadow `main/wrf.exe` matching the canonical executable, `rsl.*` logs, and generated `.f90` files paired with `.F` sources were moved under the private quarantine receipt. The shadow has no copied objects, module files, generated `.f90` pairs, or `libwrflib.a`. The plan pins the canonical archive SHA and requires its exact path in the recorded link argv, plus fresh target object and executable paths.

The selected 20-second LC05 run binds the pristine namelist, scheme-specific effective namelists, runner, configuration sources, all three active files resolved by the runner, and hashes for the preprocessing, compiler, linker, WRF standardizer, GCC/Xcode subordinate executables, and relevant environment, including SDKROOT, deployment target, developer directory, and NetCDF configuration inputs. The configuration plan pins Darwin GNU/gfortran+gcc Open MPI `dmpar` menu option 35 and basic nesting option 1 as stdin bytes `35\n1\n`; the planned stdin SHA is recorded and checked against both plan fields. The environment now pins SDKROOT to the exact output of the pinned `xcrun --show-sdk-path`, verifies SDK version 27.0, and hashes `SDKSettings.json`. The current canonical configuration is GNU Open MPI `dmpar` with `NETCDFPATH=/opt/homebrew`. The disposable runner had `NETCDF` unset and PATH selected MacPorts `nc-config`, so the plan explicitly requires `NETCDF=/opt/homebrew` and `NETCDF_C=/opt/homebrew`, pins Homebrew `nc-config`/`nf-config` paths, hashes, versions and expected outputs, and rejects mixed MacPorts NetCDF paths. The configure script SHA and these exact environment roots bind the expected call sites; the guarded ledger records post-config probes of their pinned commands, not an operating-system trace of configure's internal subprocesses. The generated `configure.wrf` SHA and captured stdout markers bind the resulting configuration. The plan also pins `perl5`, `m4`, and `python3`; the guarded child receives only the hashed environment allowlist, excluding unpinned ambient variables. The `arch/configure.defaults` menu source is hashed.

The plan fixes configuration launches to `/bin/bash ./configure` and `/bin/bash ./apply_kdm6ad_config.sh`. The only certified entry point is `python3 harness/s10_guarded_exec.py --stage configure-pipeline`, which launches both commands in one process and runs apply only after that invocation's configure succeeds; standalone configure/apply CLI stages are unavailable. It requires an out-of-band trusted plan SHA, the configure-only resource receipt, exact captured stdin, pinned shell/script hashes, clean canonical/shadow config inputs, and fresh pre/post disk and empty-root checks. Before the first subprocess it creates a plan-bound one-shot marker with exclusive file creation; the ledger records that marker, both stdout/stderr hashes, command order, and configure.wrf hashes. The runner and later prelink reject WRF's `One of compilers testing failed!` marker even when the configure shell exits 0. Prelink rejects records without the matching ledger and marker. A failed attempt consumes its marker and cannot be retried with that same local preflight. The marker and ledger are local workflow state, not cryptographic protection against a privileged actor deleting files; the coordinator resource approval must independently bind the final plan, guarded ledger SHA, generated configure.wrf SHA, full output estimate, measurement, both S15 release pins, and empty-root snapshot before any native build evidence is accepted. The attempt-three plan permits one specific shadow-only patch to `apply_kdm6ad_config.sh`: the guard verifies the canonical hook hash, private patch hash, pinned patch tool/argv, and exact reconstructed shadow bytes. All other configuration inputs remain canonical-equal. Direct unmanaged shell execution is outside certified S10 evidence. Preprocess, object, and link commands remain unsupported by this plan and are rejected before `subprocess.run`; a later plan must pin exact argv templates and add a reviewed build executor. Configuration logs and stdin captures stay in a dedicated S10 evidence directory, outside the reviewed empty `S10/build-clean` root.
The configure-only resource-preflight CLI also requires `--trusted-plan-sha256 <coordinator-pinned SHA>`; it checks raw plan bytes before parsing JSON or running any plan-selected command. Supply the coordinator's out-of-band digest after review, not a value read from the plan itself.
