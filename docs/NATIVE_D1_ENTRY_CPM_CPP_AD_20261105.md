# 바깥 `entry_cpm` 생산·전달과 D1 조건부 C++ 미분

## 같은 호출의 값 연결

선택한 native `(203,149)` 열의 39층, `runtime_call=one_step_call=2`에서, 20초 호출의 바깥 QV와 `entry_cpm`을 새로 기록했다. coordinator가 받은 인자와 D1 진입 QV, preamble의 재계산 열용량, 덮어쓴 뒤의 열용량도 같은 호출에서 기록했다. [공개 패킷](../harness/evidence/native_d1_entry_cpm_cpp_ad_2026-11-05/README.md)은 9,750행이며, 부모 캡처 9,516행의 순서·자료형·원시 단어를 모두 보존한다.

39층 모두 다음 경로가 원시 f64 비트로 이어진다.

`runtime QV → D1 QV`, `runtime entry_cpm → coordinator 인자 → 적용 preamble cpm → D1 소비 cpm`.

`cpm=1004.5(1−max(QV,10⁻¹⁵))+1846.4 max(QV,10⁻¹⁵)`를 별도 스칼라 연산으로 다시 계산해 runtime 기록값과 대조했다. 선택 16층의 QV는 `0.007321097422391176`, cpm은 `1010.6636319199112`다. 이 첫 subcycle에서는 preamble이 현재 QV에서 다시 계산한 cpm도 바깥 값과 39층 모두 같다. **값이 같다는 사실만으로 이후 subcycle에서 바깥 cpm이 재사용되는 동작을 실측했다고 볼 수는 없다.** 소스는 바깥 cpm을 루프 전에 한 번 만들고 각 one-step에 전달하지만, 이번 native 기록은 첫 subcycle 한 번이다.

원래 입력 체크포인트에서 READY 체크포인트를 준비하는 동안 `WE_JUST_D01_LBC`의 int32 원소 한 개가 1만큼 달라진다. 따라서 원본과 READY가 원시 비트로 같다고 주장하지 않는다. 계측 off/on 두 실행은 동일한 READY 해시와 소스·오브젝트·실행파일·입력을 사용했으며, 전체 종료 체크포인트 SHA-256은 모두 `225d2cabe8a466304c06ba1a04638b84c8456b8477326b6852c9217360440070`이다. 이전 #538 실행과도 같다. 계측을 제거하면 runtime·coordinator의 부모 소스 바이트가 복원된다. 비공개 실행파일·DSO·전체 체크포인트는 공개된 영수증과 해시로 연결했으며, 공개 CI가 그 바이트를 새로 빌드하거나 재해시하는 것은 아니다.

## 바깥 QV와 현재 D1 QV의 접선 구분

같은 native archive에 연결한 격리 C++ 그래프에서 바깥 QV와 D1 진입 QV를 두 독립 입력으로 두었다. `compute_cpm`은 바깥 QV를 소비하고, preamble의 새 cpm은 D1 QV로 계산하되 D1에 넘기기 전에 바깥 값으로 덮는다. 기존 #540 출력 25개에 두 cpm을 추가한 **27개 기준 출력이 모두 원시 비트로 일치**한다. 세 상대 QV 방향의 주요 JVP는 다음과 같다.

| 방향 | 적용 `entry_cpm` | 덮어쓰는 preamble cpm | D1 NR | D1 온도 |
|---|---:|---:|---:|---:|
| 바깥 QV만 | `+6.163631919911133` | `0` | `+0.04155892392198225` | `+0.0003038600461751968 K` |
| D1 QV만 | `0` | `+6.163631919911133` | `0` | `0` |
| 둘을 함께 | `+6.163631919911133` | `+6.163631919911133` | `+0.04155892392198225` | `+0.0003038600461751968 K` |

하한이 비활성인 이 지점에서 (\delta c_{pm}=(1846.4-1004.5)\delta QV\)이다. 공동 방향의 기존 25개 JVP 성분은 #540의 QV 방향과 정확히 같다. 실제 C++ JVP를 별도 Python 생산 연쇄와 비교하고, 검증된 JVP 벡터에서 계산한 한 출력 가중치의 내적을 저장된 C++ JVP·VJP 내적과 각각 대조한다. 세 방향의 양끝점마다 표현된 실제 입력 간격을 사용하고, QV 하한·따뜻한 융해·눈/싸락눈 적용 제한·진입/후속 ProgB 분기를 확인한다. C++–Python JVP 최대 절댓값 차이는 `2.7755575615628914e−17`, 최대 정규화 FD–JVP 잔차는 `1.5429507012332255e−8`이다. 이 VJP 검증은 한 가중치의 전치 관계이며 성분별 또는 임의 출력 seed 검증은 아니다.

## 해석 범위와 다음 조건

이번 외부 QV·D1 QV 분리는 **격리 C++ 단계의 조건부 교란**이다. 실제 호스트를 두 QV 방향으로 각각 교란해 실행한 결과가 아니다. 침강은 QV를 그대로 전달한다. 여러 subcycle에서 현재 D1 QV가 바뀐다면 그 원인은 그 사이의 미세물리 상태 갱신이며, runtime의 바깥 `entry_cpm`은 소스상 그대로 전달된다. 이 차이를 실제 native 값으로 확인하려면 두 번 이상 subcycle이 도는 사례에서 첫 갱신 뒤 QV와 다음 preamble cpm, 덮어쓴 cpm을 함께 기록해야 한다.

운영 f32, 전체 subcycle·호스트·C ABI JVP/VJP, QNICE 물리 단위, 과정별 수지와 GK2A–RTTOV 목적함수 민감도는 이 자료로 확정되지 않는다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`로 유지한다.
