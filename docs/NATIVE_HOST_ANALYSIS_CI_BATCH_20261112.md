# 선택 호스트 열 분석과 Oracle 중복 census 정리

이 묶음은 #586에서 저장한 native `(203,149)` 한 열의 입력·출력과 단계 자료를 **새 물리 호출 없이** 확장 분석하고, Oracle CI의 동일한 1시간 아카이브 census 중복 계산을 테스트 범위 안에서 줄인다. 물리 계산·C ABI·운영 f32 기본값은 바꾸지 않는다. 근거는 [출력별 분석 패킷](../harness/evidence/native_host_batch4_analysis_2026-11-12/README.md), [#586 원자료](../harness/evidence/native_host_batch3_shared_2026-11-12/README.md), [단위 측도 표](NATIVE_HOST_NUMBER_MEASURE_GATES_20261112.md)다.

새 출력별 수치 분석의 411개 안정·해상 행은 TH/QV/QC/QR/QS/NC/NR에 분포한다. 수치 스케일은 검증 편의를 위한 좌표이며 물리 불확도나 단위 승인이 아니다. NC=0의 양의 방향은 NC16 단측 FD가 보폭의 역수에 따라 커지는 반면 JVP는 유한하게 남는다. 원인을 불연속·AD 버그로 단정하지 않고, 다음 공통 계측의 NC 초기화/하한/조건분기 관측 대상으로 지정한다.

## 계산비용과 시험 분리

기존 Oracle pytest 시간 계측에서 두 1시간 census 시험은 각각 약 141초였고, 공통 아카이브·계획을 사용한다. 이번 변경은 **테스트 전용 fixture**에만 재사용을 넣고 `harness/streaming_ice_census.py`와 생산용 1시간 replay를 수정하지 않았다. 파일 경로·SHA·계획을 호출 때마다 확인하고, 첫 재생 직후 파일 해시도 다시 확인한다. 서로 다른 시험에는 결과의 깊은 복사본을 넘긴다. 따라서 하나의 시험이 결과를 변조하거나 입력 파일이 바뀌면 나머지 시험이 이전 계산을 묵시적으로 사용하지 않는다. 합성 변조 시험과 실제 1시간 쌍 실행을 각각 확인했다. **로컬 한 번의 절감 관측**을 다른 CI runner의 확정 시간 절감으로 일반화하지 않는다.

저장 분석 suite는 일반·`python -O`에서 재계산 가능하며 새로운 KDM/RTTOV 호출을 하지 않는다. 새 아카이브 census 캐시는 pytest 세션 밖에 저장되지 않고, 변경된 코드·입력·계획을 다른 실행으로 넘겨 재사용하는 실험 resume 기능도 아니다.

## 다음 한 계측 빌드의 사전 조건

[공통 계측 목록](NATIVE_HOST_BATCH4_COMMON_CAPTURE_20261112.md)은 세 중심에서 NC·PII·TH·QV 방향의 최대 45개 입력과 live rate-cap·NC 하한 접선, 적용 침강 departure/arrival, 총강수, 과정 후·cleanup 후 상태, 열·BG 모멘트를 함께 요구한다. 값 전용 계측의 on/off 원시 출력 일치가 먼저 통과해야 한다. `10⁻⁶` 상측 PII가 안정·해상되지 않거나 NC=0 원인이 미계측이면 추가 보폭을 자동으로 늘리지 않고 결측과 원인을 기록한다.

같은 입력의 질량·수농도·체적 측도, 실제 호스트 finish와 39/40층 native profile, RTTOV 지원집합과 BT/비용 미분은 이후 별도 계약이다. `scientific_status`와 `physical_unit_status`는 계속 `INCONCLUSIVE`다.
