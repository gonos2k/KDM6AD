# 동쪽 광학 K의 KMA 좌표 변환 인자 독립 계산

[동쪽 10개 프로파일의 K·방향차분](NATIVE_EAST_OPTICAL_DERIVATIVE_20261031.md)에서는 원시 RTTOV K에 저장된 좌표 인자를 곱해 KMA 밝기온도 민감도를 만들었다. 이번에는 GG·PP 두 기준의 **10프로파일×7채널, 총 140개** 저장 복사량에서 그 인자를 원본 계수와 보정표로 독립 재계산했다. 새 RTTOV·K 호출은 없다. [오프라인 재생 설명](../harness/evidence/east_optical_coordinate_factor_2026-10-31/README.md)

원시 TOTAL 복사량을 `R`, KMA 밝기온도 지도를 `f`, RTTOV native 밝기온도 지도를 `g`라 두면, 입력에 대한 KMA 좌표 미분은 **`f′(R)/g′(R)`을 native BT의 K에 곱한 값**이다. 재생기는 별도 RTTOV 계수 파일의 `FILTER_FUNCTIONS` 채널 10–16과 저장소의 KMA 보정 JSON을 **각각 SHA-256으로 확인한 같은 바이트**에서 해석한다. 원시 K 복사량 140개는 저장된 TOTAL과 원시비트로 비교한다.

| 독립 스칼라식과 저장 자료의 최대 차이 | 결과 |
| --- | ---: |
| `f′(R)/g′(R)` 좌표 인자 | **7.771561172376096×10⁻¹⁶** |
| KMA BT | **1.1368683772161603×10⁻¹³ K** |
| native BT | **5.684341886080802×10⁻¹⁴ K** |
| 변환된 얼음 함량·직경 K의 상대 차이 | **8.822647233090335×10⁻¹⁶** |

두 광학 입력의 K 슬롯은 `HYDRO7`의 **g/m³당 K**, `HYDRO_DEFF7`의 **µm당 K** 좌표로 읽고, 채널·층·수상 종류의 순서를 확인했다. 저장값과 재계산값을 원시비트까지 같다고 요구하지는 않는다. 스칼라 `log1p` 식과 기존 벡터 연산의 대수 순서·libm 반올림이 달라질 수 있어, 재생기는 현재 입력에서 충분히 작은 **실용적 binary64 오차 한계**를 사용한다. 이는 임의의 libm·부동소수점 환경에 대한 엄밀한 정리가 아니며, 과학적 FD–K 합격 허용오차도 아니다.

검증에 사용한 전체 계수 파일 SHA는 `73401691b9e5777daf0e4d8ba6d77dfc912c0d32bd8b70937886fcd91b54a7b5`다. 파일 헤더에서 **계수 행 재배포 허락을 확인하지 못해** 공개 패킷에는 수치 행을 넣지 않았다. 따라서 공개 재생에는 해당 원본 파일을 별도로 제공해야 한다. 채널별 `gamma` 값은 0이 아니지만, 현재 native BT 좌표식에는 사용하지 않는 전송 보정 항으로 소스에서 확인했다. 이 검사는 저장된 복사량에 대한 좌표 변환을 보강할 뿐, 실행 당시 로드된 외부 라이브러리·전체 호스트/QNICE 미분이나 경계 물리 수지를 인증하지 않는다. 과학적 판정은 **`INCONCLUSIVE`**로 유지한다.
