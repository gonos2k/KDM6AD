# 실제 호스트 선택 열의 f64 DA 경로와 TH16 활성화 전이

이번 [증거 패킷](../harness/evidence/native_host_column_f64_da_2026-11-12/README.md)은 #580에서 공개한 native `(203,149)` 열의 **624개 f32 입력 단어**를 각각 정확히 f64로 확장해 `kdm6_step_ad_c`에 넣었다. 상태 12개·forcing 4개와 39층 순서, XLAND=2, 20초 시간 간격, `ncmin_land=ncmin_sea=10`을 유지한다. 각 값의 f32 왕복 비트도 확인한다. 호출은 **B=1 f64 Legacy DA 커널**이며, 원래 WRF 전체 타일의 f64 실행은 아니다. 런타임은 subcycle 시간 `dtcld`를 여전히 f32로 다루므로 모든 내부 연산이 순수 f64라는 뜻은 아니다. 이번 미분에서는 forcing을 고정하고 초기 온위 TH16 상태 좌표만 변화시킨다.

## f32 값 계산과 f64 DA 계산은 다른 맵

f64 기준 출력을 f32로 반올림해 운영 f32 출력과 비교하면 468개 상태 단어 중 **101개가 다르다**. 따라서 #582의 f32 인접 경계나 출력 차이를 f64 미분으로 옮기지 않았다. 각 f64 입력에서는 값 전용 호출과 그래프 호출의 468개 출력 원시 단어가 일치했다.

계측한 f64 활성화 단계의 `sw_percent ≥ 0.48`과 기록된 활성화 비율 `≥ 1`을 각각 탐색했다. 두 판정은 모두 다음 **인접 f64 TH16 입력 단어**에서 바뀐다.

| 값 | 낮은 TH16 `4074005089907cc6` | 높은 TH16 `4074005089907cc7` |
| --- | ---: | ---: |
| 초기 잠재온도 | 320.01966244163884 K | 320.0196624416389 K |
| 활성화 시점 `sw_percent` | 0.4800000000002136% | 0.4799999999997473% |
| 상한 전 pow | 1.000000000000267 | 0.9999999999996841 |
| 선택 비율 | 1 | 0.9999999999996841 |
| raw rate / NCCN cap | 5,000,000 / 5,000,000 | 4,999,999.9999984205 / 5,000,000 |
| 최종 NC16 | 100,000,000 | 99,999,999.99996841 |

입력 간격은 **5.684341886080802×10⁻¹⁴ K**다. 높은 입력−낮은 입력의 NC16 차이는 **−3.159046173095703×10⁻⁵**, 출력 f64에서 **2,120 ULP**다. 이 값은 이산 끝점 차이이며 경계 도함수가 아니다. 전체 입력 공간의 경계 유일성도 입증하지 않는다.

## 내부점의 JVP·VJP와 독립 값 차분

전이의 양쪽에서 0.01 K 떨어진 엄격한 내부점을 선택했다. 각 내부점과 세 보폭 `10⁻³`, `10⁻⁴`, `10⁻⁵ K`의 양끝에서 **기록된 활성화 비교 마스크**가 유지됐다. 이는 모든 미세물리 분기가 같다는 검사로 확대하지 않는다. JVP는 초기 TH16에 1 K 방향을, VJP는 최종 NC16에 단위 cotangent를 사용했다. 각 468개 성분의 f64 접선을 보존한다.

| 내부 분기 | NC16 JVP | NC16-seeded VJP의 TH16 성분 | `h=10⁻⁵ K` 중앙차분 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 비율 = 1 | 0 | 0 | 0 | 세 보폭 모두 NC16 끝점 원시 단어가 같아 비영 신호를 해상하지 못함 |
| 비율 < 1 | −788,214,669.5459847 | −788,214,669.545985 | −788,214,671.7987962 | 표현된 입력 간격 기준 상대 잔차 **2.8582×10⁻⁹** |

비율 `<1` 쪽에서 `h=10⁻³`과 `10⁻⁴ K`의 상대 잔차는 각각 **1.8696×10⁻⁵**, **1.8734×10⁻⁷**로 보폭을 줄일수록 감소했다. 비율 `1` 쪽의 정확한 0은 상대정확도 합격 건수로 세지 않는다. 이 비교는 선택된 상태 출력의 국소 민감도 근거이며 독립된 물리과정의 기여 분해는 아니다.

## rate-cap 동률의 별도 연산자 시험

현재 연구 브랜치 coordinator의 `torch::minimum(raw_rate, NCCN_rate_cap)` 구조를 같은 Torch 의존 라이브러리로 링크한 **독립 두 입력 f64 C++ 시험**에서 확인했다. raw가 cap보다 작을 때 JVP/VJP 가중치는 `(1,0)`, 클 때 `(0,1)`, 정확히 같을 때 `(0.5,0.5)`였다. 동률의 단측 값 차분은 방향에 따라 달라 AD 접선과 일반적으로 같지 않다. 이는 해당 연산자 빌드의 관측된 규칙이다. 영수증의 coordinator SHA는 시험 준비 때 살펴본 로컬 소스 사본을 가리키며, 연구 브랜치 전체 파일의 SHA와 다르다. 두 파일의 해당 최소 연산식은 일치하지만, 이 해시를 설치 DSO의 실행 소스 증명으로 사용하지 않는다. 전체 컬럼에서 두 rate 피연산자를 독립적으로 변화시킨 결과나 설치 KDM6 DSO의 정확한 빌드 출처 인증으로 해석하지 않는다.

당시 연구 브랜치 소스는 [압축 사본](../harness/evidence/native_host_column_f64_da_2026-11-12/reviewed_source/coordinator.cpp.gz)으로 고정했다. 역사적 재생은 이후 live 소스 변경에 의존하지 않으며, 이 사본의 SHA 역시 설치 DSO의 빌드 소스를 인증하지는 않는다.

## 자료의 출처와 남은 범위

공개 재생은 f64 기준·경계·접선·차분 자료, 60개 표본의 활성화 단계 피연산자와 마스크, 대표 다섯 입력의 설치/계측 DSO 원시 출력, 네 계측 CSV, 연산자 시험 결과와 해시를 확인한다. 전체 60개 입력에서 설치/계측 출력이 같다는 결과 중 대표 다섯 입력은 원시 배열로 다시 비교하고, 나머지 55개는 저장된 실행 영수증의 범위다. 계측 켠 f64 호출은 값 전용이며, 설치·계측 끔 그래프 출력을 별도로 비교했다. 공개 CI는 비공개 바이너리·호스트 타일을 재빌드하거나 다시 실행하지 않는다.

이번 결과는 **동일 호스트 선택 열 입력의 f64 상태 AD 커널**에 한정된다. forcing 민감도, 전체 호스트 AD·substep 일정, 과정별 적용 질량·수농도·체적 수지, native center/interface pressure를 유지한 관측 입력, GK2A–RTTOV BT·비용함수 미분은 별도 대상이다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`다.
