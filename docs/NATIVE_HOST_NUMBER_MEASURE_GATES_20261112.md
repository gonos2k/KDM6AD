# 선택한 호스트 열의 수농도·물 수지 측도 확인 항목

이 문서는 #585의 [현재 소스와 원시 입력 대조](../harness/evidence/native_number_coordinate_contract_2026-11-12/report.md), #580의 `(203,149)` 열 입력, #586의 [조건부 수분 산술](../harness/evidence/native_host_batch3_shared_2026-11-12/README.md)을 한 호출의 **측도 질문**으로 연결한다. 새 호스트·KDM·RTTOV 실행 결과는 아니다. 이번 검토에서 `verify_sources.py --require-current-source`는 현재 공개 `libtorch` 4개 파일과 비공개 실행 호스트 소스 4개 파일이 #585의 SHA-256 고정값과 일치함을 확인했다. 이 일치는 설치 DSO의 빌드 계보를 증명하지 않는다.

## 실제 입력에서 생산·변환·소비·출력의 위치

| raw 필드 | 호스트 생산과 mp137 전달 | Legacy 런타임·주요 소비 | 출력과 미해결 측도 |
| --- | --- | --- | --- |
| `NCCN` → `nccn` | Registry `qnn/QNCCN` 표기는 `# kg(-1)`. 첫 스텝 `NN`은 호스트 높이·육해 프로파일에서 초기화된다. mp137은 `NN=qnn_curr`를 f32로 직접 전달한다. | C ABI field 7, `runtime.cpp`의 raw `nccn`로 직접 진입. 활성화 `ncact·dt`가 reservoir를 줄이고 구름·비 완전 증발은 수를 되돌릴 수 있다. 진입·후처리에는 수치 제한이 있다. | raw `nccn_out`이 `NN_OUT`을 거쳐 `qnn`으로 돌아간다. 프로파일의 체적형 설명과 Registry의 질량당 표기 사이의 정의가 미해결이다. |
| `NC` → `nc` | Registry `qnc/QNCLOUD` 표기는 `# kg(-1)`. mp137 `NC=qnc_curr`가 직접 전달된다. | C ABI field 8. 구름 기울기/DSD, 활성화, 완전 증발, 수치 제한이 읽고 갱신한다. #580의 native 16층 raw 입력은 0이다. | `nc_out`이 직접 반환된다. 내부 수치 바닥값·상한을 외부 질량당 단위의 물리 임계값으로 해석할 근거가 아직 없다. |
| `NI` → `ni` | Registry `qni/QNICE` 표기는 `# kg-1`. mp137 `NI=qni_curr`가 직접 전달된다. | C ABI field 9. 얼음 핵생성, slope/DSD와 침강이 사용한다. 일부 침강 기록은 있으나 모든 종의 실제 departure/arrival ledger는 없다. | `ni_out`이 직접 반환된다. 적용 수송량과 바닥 유출을 같은 측도에서 닫기 전에는 열 수농도 보존을 승인할 수 없다. |
| `NR` → `nr` | Registry `qnr/QNRAIN` 표기는 `# kg(-1)`. mp137 `NR=qnr_curr`가 직접 전달된다. | C ABI field 10. 비 기울기·따뜻한/차가운 과정·비 수농도 수송과 완전 증발이 읽고 갱신한다. | `nr_out`이 직접 반환된다. 과정별 생성·소멸과 수송량을 분리한 잔차가 필요하다. |

Registry의 `# kg⁻¹`은 **건조공기당인지 습윤공기당인지**를 정하지 않는다. 운영 `dry_number=0` 경로에는 mp137 전달점이나 `runtime.cpp`의 raw 필드 매핑에서 `rho_d` 곱셈이 없다. 별도 opt-in `dry_number=1`은 입구에서 `rho_d=rho/(1+qv)`를 계산해 네 수 필드에 곱하고, 출구에서 나누며 내부 density도 바꾼다. 이는 **다른 좌표 계약**이므로 운영 raw 단위의 소급 확정이나 이전 원시 비트 parity의 대체 근거로 사용할 수 없다. 독립 forcing AD에서의 `rho` 변화 역시 호스트가 생성하는 연동 방향 `F=G(s)`와 구분한다.

## 수분 잔차의 조건부 측도

#586의 산술은 f32 원시 단어를 정확한 십진수로 읽어 `Σ_k rho_k·delz_k·Σ(qv,qc,qr,qi,qs,qg)`의 입출력 차이에 **총강수 증가량 한 번**을 더했다. 결과 `−0.4662958822 kg m⁻²`는 `rho`가 이 `q`들과 양립하는 건조공기 질량밀도이고 `q`가 건조공기당 혼합비라는 미확인 가정 아래의 수치다. `rain` 총량에 포함된 눈·싸락눈 부분 진단값은 다시 더하지 않았다. 호스트 cleanup·수송과 같은 호출의 f64 총강수는 포함되지 않았다. 이 숫자만으로 물리 보존 실패, 특정 과정 손실 또는 운영 f32와 f64의 같은 수지를 판정하지 않는다.

## 판정에 앞서 필요한 공통 계측

1. **측도 고정:** 실제 호스트의 `rho`·`q`·네 수농도 정의가 건조/습윤 공기 질량과 체적 중 어느 기준인지 source/Registry/초기화·출력에서 일치시킨다. 잠열·모멘트와 강수 진단의 단위도 각각 고정한다. 서로 충돌하는 정의가 남으면 상태는 `INCONCLUSIVE`로 둔다.
2. **같은 호출의 실제 적용량:** 종·층·substep별 후보와 제한 후 출발량, 도착량, 바닥 유출, 상태 저장 시 반올림을 함께 보존한다. 수농도의 핵생성·응집·증발 기여는 침강 수송과 분리한다. 총강수는 부분 진단을 중복하지 않는 한 필드로 기록한다.
3. **전후 경계:** kernel 입력, 과정 후 상태, cleanup 후 상태, host finish/transport 후 상태를 구분한다. 단일 B=1 결과를 전체 WRF 타일의 내부 일정이나 동일 시각의 다른 열 결과로 대체하지 않는다.
4. **잔차 판정:** 승인된 측도로 각 과정과 전체 호출의 질량·수농도·체적·열 잔차를 재구성한다. 해상도와 f32/f64 연산 순서를 보고하고, 남은 잔차는 최초로 달라진 적용량/상태와 연결한다. 단위가 미승인인 항은 조건부 수치로만 남긴다.

현재 `scientific_status`와 `physical_unit_status`는 모두 `INCONCLUSIVE`다. 다음 계측에서는 이 필드들을 NC=0·상측 PII의 분기·살아 있는 접선과 **한 빌드·한 입력 목록**에서 함께 수집하되, 값 전용 기록을 AD 경로에서 `.item()`으로 떼어내지 않는다.
