# 동일 호스트 선택 열의 다음 계측 묶음

이 문서는 #583의 native `(203,149)` 선택 열과 20초 B=1 호출을 기준으로 **02–06·09–13**에 필요한 자료를 한 번의 계측 빌드와 공통 실행 목록으로 준비한다. 실행 승인이나 과학적 완료 판정은 아니다. 운영 f32 값 호출, Legacy f64 state AD, state+forcing AD, 원래 WRF 타일은 서로 다른 실행 경로로 기록한다. 현재 f64 패킷의 설치 DSO와 정확히 확장한 624개 입력 단어를 기준으로 고정하고, 물리 대안을 켜지 않는다.

## 이미 있는 자료와 공통 공백

#583의 대표 f64 내부점·경계점 네 곳에는 각 **19,656행**의 native 계측 CSV가 있다. 39층, substep `0·1`, **51개 stage**를 포함하며, 각 CSV에 f64 값 18,447개, Boolean 1,170개, f32 일정값 39개가 기록돼 있다. `fd_satadj_inner`에는 활성화 피연산자·마스크 33개, `runtime_full_schedule`에는 주·빙상 substep 수, `fd_state_update`·`fd_reclass`·`fd_cleanup`에는 NC/NCCN/NR 단계값이 있다. 기존 차분 `±h` 열두 끝점에는 **33개 목표층 활성화 trace만 저장**되어 있어 전 단계·전 층 분기 안정성을 확인할 수 없다. 계측 켠 f64 호출은 값 전용이고, 별도 계측 끔 그래프 호출과 원시 출력 468개를 대조하는 계약을 유지한다.

## 한 빌드와 여러 값 호출의 실행 계획

1. 기존 비공개 CSV의 51 stage 필드 목록과 `harness/same_call_water_budget.py`, `harness/ice_chain_applied_budget.py`의 적용량 계약을 먼저 대조한다. 빠진 자료만 계측에 추가하고, 계측 on/off의 **동일 입력 전체 출력 원시 비트 일치**를 게이트로 둔다. AD 그래프에는 `.item()`이나 `detach`를 끼워 넣지 않고, 값 전용 기록과 살아 있는 중간 텐서의 접선 기록을 구분한다.
2. 기준점과 양쪽 내부점에서 상태 TH/QV/NC/NCCN·혼합 방향, forcing 네 축과 필요한 혼합 방향의 그래프를 재사용한다. 각 방향의 `±h`는 별도 값 호출이며, 표현된 실제 입력 간격과 모든 채택 끝점의 분기·substep 기록을 함께 저장한다. 상태·forcing·단위·방향 정규화가 일치하는 완료 기록만 재사용한다.
3. 같은 계측 빌드에서 물 수지와 침강·과정 ledger의 입력·중간·최종 상태를 동시에 보존한다. f64 packed ABI에 없는 총강수는 동일 물리 호출의 별도 관측으로 연결하고, 선택 열 B=1 실행과 원래 전체 WRF 타일의 일정·출력을 동일하다고 가정하지 않는다.
4. 새 native host 실행은 기존 비공개 캡처가 부족한 경우에만 별도로 준비한다. 그때 타일 범위·시각·호출 번호·설치 DSO·계측 DSO·컴파일 플래그·full-column 배열·substep 일정과 native 압력·기하 자료를 함께 고정한다. 정밀도·입력·빌드·환경이 달라진 기록은 재사용하지 않는다.

현재 #583의 정확한 f64 입력·대표 CSV와 #580의 f32 host 호출은 **서로 다른 실행 증거**다. 이 계획을 실행해도 물리 수지, 전체 host AD 또는 GK2A–RTTOV 비용 미분이 자동으로 완료되지는 않는다. 수치 잔차와 미해결 단위를 그대로 보고하고, `scientific_status`와 `physical_unit_status`는 해당 계약을 충족할 때까지 `INCONCLUSIVE`로 둔다.
