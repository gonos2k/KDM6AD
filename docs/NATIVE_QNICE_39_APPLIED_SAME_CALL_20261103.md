# 같은 native 호출의 39층 QNICE 적용량

## 실행과 검증 범위

2025-07-19 00:00:40 체크포인트에서 20초를 진행한 mp137 연구 실행을
계측 off/on으로 반복했다. 좌표는 native `(164,242)` 열의 39개 층이며,
한 MPI rank·한 스레드, 타일 2, `runtime_call=2`, `one_step_call=2`,
`B=32248`, `b_zero=22617`이다. 실행 설정은 실험적
`KDM6_ICE_FACTORIAL_MODE=norm_actual`, `KDM6_QR_TRANSPORT=actual_departure`다.
REAL4 호스트 입력을 f64 작업 상태로 넓히는 기존 연구 ABI를 사용했다.

최종 실행 파일 SHA-256은 `54fc156b5eb98d8ba143775079b78ed68ce82858639430dfa0954a6d054bbb17`,
실제로 로드한 DSO는 `976b4110b81f64e8e63cb7162642b2b00002af0e9b074520c92eeb2cd9126422`다.
입력 계획과 실행 소스·아카이브·오브젝트의 해시는 [재생 패킷](../harness/evidence/native_qnice_39_applied_2026-11-03/README.md)에 묶었다.
같은 빌드의 계측 off/on 종료 체크포인트 파일은 모두
`225d2cabe8a466304c06ba1a04638b84c8456b8477326b6852c9217360440070`으로 일치했다.
공개 검증기는 보존한 입력·실행 영수증과 선택 원시 기록을 대조한다.
비공개 실행 파일과 전체 체크포인트 바이트 자체는 재배포하지 않는다.

## 입구와 C3 전 상태의 연결

호스트가 `moist_physics_prep_em` 뒤에 기록한 AL·ALB·RHO·QV·QNICE
39층에서, f32 연산 순서대로 계산한 `1/(AL+ALB)`는 RHO의 원시 비트와
모두 같았다. RHO/DEN·QV·QNICE의 호스트 f32 값도 C++ 진입 f64 값과
39층 모두 정확히 연결됐다. 층 순서는 호스트의 아래→위에서 침강의
위→아래로 바꿔 대조했다. 전체 39층의 ABI 입력은 별도 포착하지 않았고,
기존 [C5 동일 호출 패킷](../harness/evidence/native_c5_limiter_call_2026-11-01/README.md)의
21·23층 ABI 입력과 C3 입력을 같은 원시 비트로 다시 연결했다.

호출 입력에서 침강 뒤까지의 두 선택 층 NI 변화는 실제 적용 유출·유입량으로
다음처럼 설명된다. 값은 **기록된 C++ NI 수치 좌표**이며 물리적 단위는
아직 확정되지 않았다.

| native 층 | 침강 전 NI | 적용 유출 | 적용 유입 | 침강 후 NI | 순변화 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 21 | 0.1376752108335495 | 0.0017857102530552098 | 40.591479729160824 | 40.72736922974132 | +40.58969401890777 |
| 23 | 116719.8203125 | 172.77053588541446 | 1.10466000736014 | 116548.15443662195 | −171.66587587805407 |

이번 `norm_actual` 보존형 침강은 위층의 **제한 후 실제 유출량**을 다음
층 유입에 사용한다. 기존 legacy 침강의 별도 유입 제한식을 적용하지 않는다.
전체 39층에서 적용률, 유출·유입, NI 저장값과 `fall_ni` 저장값을 실행
순서의 f64 원시 비트로 재생했다. 얼음 침강 세부 단계는 1개이며, 대상
열의 모든 층에서 단계 게이트가 활성이다. 이 호출의 유출 저장량 제한과
층두께 하한은 작동하지 않았다. 별도 합성 C++ 시험은 유출 제한이 작동하는
39층 분기를 재생한다.

침강 뒤부터 C3 입력까지는 D1·균질 동결·입자수 재작성 A·D2–D4·재작성 B의
39층 전후 기록을 순서대로 연결했다. D1, 균질 동결, D2–D4, 재작성 B의
NI 원시 비트 변화는 없었다. **재작성 A는 25·20·19·18·17·16층의
NI를 바꿨다.** 그 단계의 기록된 `Σ NI·Δz` 차이는 약 `+49027.35812796282`다.
이 값은 재작성 전후의 관측 차이다. 이 패킷을 작성할 당시에는 재작성
계수식까지 독립 재계산하지 않았다. 후속 [재작성 A 국소 재생·미분
검증](NATIVE_QNICE_SNAP_A_LOCAL_AD_20261103.md)에서 39층 출력의 원시
비트와 여섯 변화층의 조건부 미분을 대조했다. 최종 DSD 입자수
재작성에서는 39층 모두 NI 변화가 없었다.

## 상태 재생과 수지의 구분

침강 전후 상태는 기록된 적용량으로 원시 비트까지 재생된다. 그러나
`Σ NI·Δz`의 열 전체 수치 변화, 층간 전달 차이와 대입 반올림 잔차는
서로 다른 진단이다. 이번 자료의 값은 다음과 같다.

| 진단량 | NI 수치 좌표 × 층두께의 값 |
| --- | ---: |
| 침강 중 열 전체 변화 | `−2.3794033831152292e−11` |
| 바닥 실제 유출 기여 | `0` |
| 최대 절댓값의 계면 전달 차이 | `3.0448629728674348e−12` |
| 정확합으로 계산한 산술 수지 잔차 | `+2.6382586313862565e−11` |

정확합은 **이미 저장된 f64 값들**의 합산에 적용했다. 상태 대입에서
생긴 반올림은 되돌리지 않는다. `fall_ni`는 적용 유출량을 시간 간격으로
나눈 값을 누적하므로, 누적값의 차이를 실제 적용 유출량 대신 쓰지 않았다.
QNICE의 생산·restart 기준과 밀도 변환 계약이 미확정이므로 이 표를
물리적인 입자수 보존 판정으로 확대하지 않는다.

## 과거 실행과 남은 범위

최종 빌드는 이전 PR457-v3의 f64 호스트 아카이브를 기준으로 하고,
호스트 계측 `solve_em.o`와 C++ 계측 DSO를 별도로 고정했다. 앞선 C5
두 층 전체 캡처 파일과 이번 선택 캡처 파일의 SHA-256은 정확히 같다.
반면 **전체 종료 체크포인트**는 과거 C5 실행과 같지 않다. [비공개
체크포인트의 고정 스캔 기록](../harness/evidence/native_qnice_39_applied_2026-11-03/raw/historical_c5_compare.txt)에서
652개 변수 중 650개가 일치했고, QNCLOUD 15개 셀과
RE_CLOUD 1개 셀이 달랐다. 따라서 이전 실행과의 전체 영역 parity를
주장하지 않는다. 이번 off/on 비간섭은 **같은 최종 빌드 안에서** 확인했다.
초기 체크포인트와 READY 상태 비교에도 `WE_JUST_D01_LBC` 한 요소의
차이가 기록됐다.

첫 격리 빌드는 운영 f32 ABI가 실험적 QR 경로의 f64 입력 검사에서
중단됐다. 다음 빌드는 침강이 실제 사용한 보존형 함수가 아닌 legacy
함수만 계측했고, 세 번째 빌드는 전역 `one_step_call`을 내부 단계 번호로
잘못 표시했다. 이 실패·중간 실행은 각각의 영수증과 함께 비공개로
보존하고 최종 자료에 섞지 않았다.

`scientific_status: INCONCLUSIVE`, `physical_unit_status: INCONCLUSIVE`를
유지한다. 같은 호출의 적용량과 수치 전달은 확인됐지만, 원래 QNICE의
생산·restart 단위, 물리적 입자수 수지, 운영 f32 일치, 전체 호스트의
JVP/VJP와 RTTOV 민감도는 별도 검증 범위다.
