# 실제 C++ 그래프의 D1→ProgB 조건부 국소 미분

[같은 호출의 D1 이후 ProgB 기록](NATIVE_D1_POSTMELT_PROGB_AD_20261104.md)은
실행된 C++의 기준값을 포착하고 별도 Torch 재표현으로 미분을 검사했다.
이번에는 그 native 빌드에 기록된 **동일한 `libkdm6.a` 바이트**에
격리 C++ 실행기를 연결해, 실제 `melting_torch` →
`apply_melt_freeze_inline` → `progb_param_torch`의 그래프를
미분했다. 입력은 선택한 `(203,149,16)`의 호출 번호 2에서 저장한
f64 원시 단어다. [공개 재생과 범위](../harness/evidence/native_d1_progb_cpp_ad_2026-11-04/README.md)

## 기준값과 미분 실행

C++ 실행기의 눈·싸락눈 실제 융해량, D1 QG·BRS·NR·온도, 후속
ProgB 밀도·BRS·`avtg/bvtg` **10개 출력은 모두 native 캡처와 원시
f64 비트가 같다.** 실행기의 오브젝트·실행 파일, 연결한 정적
라이브러리, 사용한 Torch 2.13.0 라이브러리와 입력 캡처의 SHA-256을
빌드·실행 영수증에 고정했다. [실제 C++ 출력](../harness/evidence/native_d1_progb_cpp_ad_2026-11-04/raw/cpp_result.json) ·
[출처 기록](../harness/evidence/native_d1_progb_cpp_ad_2026-11-04/raw/build_receipt.json)

JVP는 운영 `Handle::jvp`와 같은 **이중 역전파 방식**으로, VJP는
C++ `torch::autograd::grad`로 계산했다. D1 진입 QV 상대, T의 1 K
절대, QG 상대, 지속 `rhox` 상대 방향을 시험했다. 아래는 직접
C++ 그래프에서 나온 두 출력의 방향 접선이다.

| D1 입력 방향 | 후속 밀도 JVP | 반환 BRS JVP |
| --- | ---: | ---: |
| QG16 상대 | `+1163.0564367765057` | 거의 `0` |
| 지속 `rhox`16 상대 | `−263.13550436867445` | `+1.3585452844342611e−8` |
| QV16 상대 | `+1.3877787807814457e−17` | `−2.5627159771234574e−12` |
| T16 절대 1 K | `+5.684341886080802e−14` | `−8.914889997487064e−9` |

10개 출력·네 방향에서 독립 해석식과 C++ JVP의 최대 절댓값 차이는
`5.684341886080802e−14`다. 가중 출력에 대한 실제 C++ VJP·JVP
내적과, 같은 분기를 유지한 실제 표현 간격의 중앙차분도 대조했다.
차분 양 끝의 출력 10개 역시 독립 스칼라 계산과 원시 비트가 같다.
`max(1,|JVP|)`로 정규화한 최대 FD–JVP 잔차는
`2.539004969644758e−8`이다. QV·T의 극소 밀도 응답은 QG와 BRS
변화의 상쇄 및 반올림 규모에 있어 물리 신호로 해석하지 않는다.
QV 밀도 접선의 해석식 대조에는 `2e−17`의 별도 절댓값 한도를 두며,
기록된 값에 `5e−13`을 더하고 해시를 다시 계산한 시험 출력은 전체
재생 경로에서 거부한다. T 방향의 상쇄 성분은 기준 출력의 ULP에
근거한 한도로 검사한다.

QG 상대 반보폭 `10⁻⁴`의 양의 끝점은 실제 C++에서도 밀도 상한
`900`을 선택한다. 국소 미분 비교에는 양 끝이 상한 안쪽인
`10⁻⁵`, `10⁻⁶`, `10⁻⁷`을 사용하고, 상한 교차는 별도 유한 변화로
기록한다. [분기 결과](../harness/evidence/native_d1_progb_cpp_ad_2026-11-04/results.json)

## 범위

이 검증은 **포착된 D1 진입 상태에서 시작하는 조건부 C++ 단계
그래프**다. 앞선 침강·지속 ProgB 진단의 생산 이력, 기울기·절편,
밀도·압력과 다른 상태, 기하·세부 단계 일정은 고정한다. 실제 교란
호스트 호출이나 공개 C ABI의 최종 상태 JVP/VJP를 재실행한 결과는
아니다. C++ 실행은 로컬 격리 빌드에서 수행하고 출력과 영수증을
보존했다. CI의 공개 Python 재생은 이 출력과 소스·입력 해시를
검증하지만, 비공개 정적 라이브러리나 실행 파일을 다시 빌드하지는
않는다. 운영 f32, QNICE 물리 단위, 전체 호스트·RTTOV 미분도 남아
있어 `scientific_status: INCONCLUSIVE`와
`physical_unit_status: INCONCLUSIVE`를 유지한다.
