# 실제 QI 계면 적용량과 활성 D1 융해의 같은 호출 기록

기존 `(164,242)` 열에서는 D1의 눈·싸락눈 융해 적용량이 39층 모두 0이었다.
같은 native 5 km 체크포인트에서 따뜻한 층에 눈·싸락눈이 있고 바로 위층에
얼음이 있는 열을 선별했다. 선택한 `(203,149)` 열의 **실제 20초 mp137
호출**에서는 native 17→16층의 QI 전달과 16층 D1 융해가 함께 기록됐다.
[실행·재생 패킷](../harness/evidence/native_qi_applied_d1_active_2026-11-04/README.md)

| 기록 항목 | 값 |
| --- | ---: |
| 17층 QI 실제 유출 | `1.524431280686188e−10` |
| 16층 QI 실제 유입 | `1.5404679459033794e−10` |
| 16층 침강 후 QI | `1.5404807243815997e−10` |
| 16층 D1 입력 온도 | `274.6803185248609 K` |
| 16층 눈 융해 적용량 | `−1.3202611149878743e−4` |
| 16층 싸락눈 융해 적용량 | `−1.2225833390863422e−5` |
| 16층 얼음 융해 적용량 | `+1.5404807243815997e−10` |
| 16층 D1 온도 | `274.6803185248609 → 274.6303629975879 K` |

기록된 적용량과 `350000/cpm_safe`를 곱한 온도 항은 눈 약
`−0.04572158 K`, 싸락눈 약 `−0.004233893 K`, 얼음 약
`−5.334794e−8 K`다. 이 값은 실행 순서의 **산술 기여**이며,
눈·싸락눈 원래율의 생산식까지 독립 검증한 결과는 아니다.

QI 유입량은 위층의 **제한 후 실제 유출량**에 기록된 밀도·층두께 비율을
적용한 값이다. 그래서 두 층의 혼합비 좌표 숫자는 같지 않다.
새 선택 열 캡처 4,485행의 호출·타일·층·자료형·순서를 확인하고,
39층의 QI 유출 후보·실제 유출·유입·상태 저장·누적 진단을 실행 순서로
재계산해 f64 원시 비트와 비교했다. D1의 QI 완전 융해, QV→열용량,
QC·QI·NC·NI·온도 저장도 **기록된 눈·싸락눈 적용량**을 사용해 39층
원시 비트로 재생했다.
runtime 진입 QV와 D1 입력 QV도 39층 모두 비트 일치하며, 한 ULP를
바꿔 해시를 다시 계산한 입력은 이 연결 검사에서 거부된다.

계측 off/on 종료 파일의 SHA-256은 서로 같고 기존 실행 종료 파일과도
같다. QI 수지 결과는 상태 재생과 구분한다. 저장된 f64 값의 정확합으로
계산한 `Σ QI·DEND_safe·DELZ_safe` 변화는 약 `+2.5872e−21`, 계면
불일치 최대 크기는 `3.6187e−23`, 산술 수지 잔차는 `+2.5494e−21`이다.
개별 상태 저장에서 생긴 반올림은 정확합을 해도 사라지지 않는다.

이번 기록은 **비영 눈·싸락눈 적용량과 QI 계면 적용량의 직접 관측**이다.
눈·싸락눈 원래 생성식과 제한 후보의 모든 피연산자는 아직 기록하지
않았다. 따라서 그 생산자의 JVP/VJP나 QV 교란에 따른 반응을 이번
결과로 선언하지 않는다. 다음 단계에서는 D1의 기울기·절편·열 전달
입력과 원래율·제한값을 같은 호출에 추가하고, 분기를 유지하는
끝점에서 차분과 AD를 대조해야 한다.

새 열의 호스트 AL·ALB·QV·QNICE 호출 직전 값은 직접 재계측하지 않았다.
C++ 진입·단계 값과 비공개 입력·실행 파일의 해시는 보존했지만,
QNICE의 원래 생산·restart 단위와 전체 호스트·RTTOV 미분은 별도
검증이 필요하다. `scientific_status: INCONCLUSIVE`와
`physical_unit_status: INCONCLUSIVE`를 유지한다.
