# D1 싸락우박 융해의 적용량·수 변환 계수 접선

## 실제 소비값과 저장 순서

기존 native `(203,149)` 열의 39층·20초 f64 호출에서 초기 17층 QG·BRS를 교란한다. 이번 패킷은 D1이 실제 소비한 **음의 융해 적용량** `A=pgmlt_capped`를 살아 있는 텐서로 추가 기록하고, 기존 `gfac_melt`, `qr1/qr2`, `nr1/nr2`와 같은 C++ 그래프에서 대조한다. 생산률 `pgmlt=A/20`과 적용량 `A`를 구분한다. [증거 패킷](../harness/evidence/native_d1_graupel_applied_cpp_ad_2026-11-08/README.md)

실행 소스는 다음 순서로 저장한다.

`QR2=QR1−A·warm_mask`, `NR2=NR1−gfac_melt·A`.

이후의 동결 항 `pfrzdtr/nfrzdtr`는 별도 저장 연산이다. 선택한 기준점과 24개 끝점에서는 warm mask가 1, `−QG_before<A<0`, `gfac_melt>0`, 두 후속 동결 항은 0이다. 25개 사례의 QR2·NR2를 **곱셈 다음 뺄셈** 순서로 재현하면 원시 f64 비트가 일치한다.

새 계측의 `c3_pre_mf_d1` 26개 필드는 기준점과 기존 공동 큰 보폭 양끝, 총 **78개 native 캡처값**과 원시 비트·자료형이 일치한다. 같은 세 사례의 `A`와 `gfac_melt`도 native 융해 생산값과 각각 원시 비트로 이어진다. 이전 #561의 208개 기준 단계값, 200개 단계 접선, 네 VJP 행과 최종 상태는 유지됐다. 다른 FD 끝점의 새 단계값은 이번 격리 C++ 값 실행 결과이며 별도의 native-host 중간 캡처는 없다.

## 공동 초기 방향의 미분 분해

한 단위의 QG17+BRS17 공동 상대 방향에서 `dQR1=dNR1=d(warm_mask)=0`이다. 저장된 실제 C++ 접선은 `dA=−6.5348297271×10⁻⁶`, `d(gfac_melt)=−11,292,516.4995`이다. 따라서 선택한 분기의 곱 미분은 다음과 같다.

| 항 | NR2·QR2 접선 기여 |
| --- | ---: |
| `dQR2=−dA` | `+6.5348297271×10⁻⁶` |
| `−gfac_melt·dA` | `+117.7588999` |
| `−A·d(gfac_melt)` | `−138.0604253` |
| **두 NR 항의 합과 실제 `dNR2`** | **`−20.3015254`** |

QG 단독·BRS 단독 방향에도 같은 입력별 식을 적용해 실제 C++ 접선과 반올림 범위에서 비교했다. 세 방향의 수치 단계 226개는 공동 방향 선형성 검사도 통과한다. `A`와 `gfac_melt`는 같은 상류 상태의 영향을 받으므로 두 항은 **한 D1 저장식의 조건부 곱 미분**이다. 각각을 물리적으로 독립적인 과정 제거 효과로 보거나 입자수 보존을 확정할 근거는 아니다.

## 차분, 출처와 다음 검증

`A`, `gfac_melt`, QR2, NR2의 **네 신호**를 실제 표현된 f64 초기 입력 간격의 양끝값과 대조한다. 기존 계측에서 밀도 상한을 유지한 7쌍의 최대 신호 상대오차는 `4.449×10⁻⁷`; 별도 cap 캡처가 없는 `10⁻⁶` 3쌍은 `1.359×10⁻⁸`이다. 밀도 900 상한을 넘는 큰 단독 교란 두 쌍은 국소 미분 판정에서 제외한다. 기준점과 각 끝점의 한쪽 차분도 검사한다.

이번 패킷은 적용량과 계수의 **소비 및 저장식**을 검증한다. 융해 원률, `gfac_melt` 원생산식, 개별 제한이 활성인 분기, 층간 침강 유입·유출과 물리 단위·과정별 수지는 별도 대상이다. 비공개 archive·실행 파일의 SHA 연결과 격리 C++ 실행은 보존했지만 공개 CI는 그 결과를 재생하며 비공개 파일을 다시 빌드하지 않는다. 운영 f32, 전체 호스트와 GK2A–RTTOV 비용 민감도도 남아 있어 `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`다.
