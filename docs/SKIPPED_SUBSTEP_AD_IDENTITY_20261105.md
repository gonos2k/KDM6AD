# 건너뛴 침강 substep의 상태·수반 항등 전달

## 확인한 불일치

Fortran의 주 침강·얼음 침강 루프는 전역 `mstepmax`까지 돌지만, 각 열의 상태·누적량 갱신은 `n ≤ mstep(i)`일 때만 수행한다. 따라서 이 조건이 거짓인 열의 **실제 적용 유출·유입량은 0**이고, 상태와 누적 침강량은 이전 값을 그대로 유지한다. 고정된 단계 수·게이트 안에서 이 분기의 JVP는 항등 전달, VJP는 같은 입력으로의 항등 누적이어야 한다.

기존 C++·Python 계산은 게이트가 0인 열에서도 후보 연산을 수행했다. 예를 들어 `falk=0`인 곳의 `min(0, QR_above)`와 최종 `clamp(...,0)`가 QR=0 경계에서 값을 바꾸지 않으면서 수반값을 남긴다. 2층 합성 시험에서 첫 열의 단계 수를 1, 두 번째 열을 5로 두면, 첫 열의 출력은 단일 열 실행과 같지만 그 입력 접선은 달랐다.

| 합성 입력과 선택 출력 | 단일 열 기울기 | 기존 2열 기울기 | 수정 후 2열 기울기 |
|---|---|---|---|
| QR=0의 2층 rain 출력+표면량, 입력 QR 두 층 | `[0.5, 5.99]` | `[0.95, 5.530625]` | `[0.5, 5.99]` |
| QI=0의 2층 ice 출력, 입력 QI 두 층 | `[0.5, 0.49]` | `[0.95, 0.030625]` | `[0.5, 0.49]` |

QR/QI가 정확히 0인 지점은 다른 과정도 분기 경계이므로, 위 숫자를 모델 전체의 양방향 물리 미분으로 해석하지 않는다. 이 시험의 판정 대상은 **건너뛴 substep을 추가해도 첫 열의 값·접선이 달라지지 않아야 한다**는 항등 계약이다. [Python 시험](../oracle/tests/test_skipped_substep_ad_identity.py)과 [C++ 시험](../libtorch/tests/test_sedimentation.cpp)은 f32·f64에서 단일 열과 2열을 각각 비교하며, 운영 연쇄처럼 매 단계 뒤 ProgB·기울기 재계산을 켠 경우도 포함한다.

## 소스 수정과 native 표적 사례

`sedimentation_chain`에서 매 substep의 계산 후보를 얻은 뒤, `n > mstep_col`인 열의 주 침강 상태 다섯 필드와 누적량 다섯 필드, 얼음 상태 두 필드와 누적량 두 필드를 **이전 텐서로 선택**한다. 활성 열의 후보 계산은 그대로 사용한다. 저장 마스크는 substep helper와 같이 `mstep_col`을 최소 1로 제한해, 잘못된 0 입력에서도 두 게이트가 어긋나지 않도록 한다. 이는 Fortran의 열별 `if`와 값·미분 계약을 맞추는 선택이며, 과정률이나 임계값을 바꾸지 않는다. [C++ 위치](../libtorch/src/coordinator.cpp) · [Python 위치](../oracle/kdm6/coordinator.py)

보존된 실험용 native 20초 호출의 선택 열 `(203,149)`은 주·얼음 단계 수가 각각 1이고, 타일 전체 최대 주 단계 수는 5다. 그 호출에서 포착한 12개 상태·39층의 C++ 진입·종료값을 별도 f64 C ABI 한 열에 넣었을 때 기준 종료 상태가 원시 비트로 일치했다. 실제 입력으로 만든 **합성 두 번째 열**의 층두께를 0.16배 하여 전역 주 단계 수를 5로 맞춰도 표적 출력 12×39와 QV·QS·QG 방향 JVP는 단일 열과 원시 비트로 같았다. 기존 코드에서는 혼합 출력 seed의 VJP가 표적 QR 19층에서 단일 열 `0`, 2열 `1.0695298723518434`로 달랐다. 수정 코드에서는 표적 VJP 전체가 단일 열과 원시 비트로 같고, 합성 열의 수반값은 0이다.

표적 QR 19층은 0이다. 여기에 양의 `10⁻⁹`부터 `10⁻⁶`까지를 넣은 별도 값 실행에서 단일 열과 2열의 표적 출력은 원시 비트로 같고, 선택한 출력 가중합의 한쪽 차분은 0이었다. 기존 2열의 비영 VJP는 이 허용 방향의 반응과도 맞지 않았다. 합성 열은 모델에서 관측한 두 번째 열이 아니며, **전역 단계 수만 맞추는 분리 시험**이다.

수정한 격리 DSO를 기존 실행파일과 입력으로 호스트에 넣은 계측 off/on 실행은 같은 전체 종료 체크포인트 SHA-256 `225d2cabe8a466304c06ba1a04638b84c8456b8477326b6852c9217360440070`을 냈다. 원래 계측 변형과도 같다. 이는 **이 한 실행의 forward 비간섭 및 변형 간 동일성**이며, 모든 운영 f32 사례의 비트 동일성은 C++/ABI 회귀시험과 별도로 판단해야 한다.

비공개 실행자료는 canonical 작업공간의 `host/research_evidence/native_d1_full_state_20261105/`와 `host/research_evidence/native_d1_full_state_mask_trial_20261105/`에 보존했다. 이전·수정 DSO SHA-256은 각각 `e737438ead33e2e07d533cc40337c041f7d430d578686571334036adc692792b`, `4c7849af3cb2a36599b968b018569d9f955b94eb38cacd58749f5b5e679a5caf`다. 수정 실행의 off/on `run_result.json` SHA-256은 각각 `a9c7476203493afb2960899e87325fc0565dd3f31016e92c1ece513f68321c49`, `935a7635eb4ea2d6ae64a26c4df5844bed5853fca78f12bcc23f642bf71650da`다. 별도 B1/B2 C ABI probe는 절대 경로로 이 수정 DSO를 로드하고 라이브러리·archive·소스·입력·출력 해시와 종료 코드를 `final_probe_receipt.json`(SHA-256 `3623a90b324a6edd33c31bbfc29e76358936dcf82d29ef7e60fc6ba2e961cf44`)에 고정했다. 이 공개 PR에서는 비공개 DSO·전체 체크포인트를 재빌드·재해시하지 않는다.

## 범위

이 수정은 `sedimentation_chain`의 건너뛴 열 미분 전달을 바로잡는다. 하위 `substep_advection_torch`와 `ice_substep_advection_torch`를 연쇄 밖에서 직접 호출한 후보값의 0 경계 접선은 이번 계약에 포함하지 않는다; 연쇄가 그 후보를 실제 저장 여부에 따라 선택한다. 같은 표적의 QV·QS·QG 전체 호출 방향차분에는 별도의 분기·보폭 검증이 필요하다. 실험 호스트는 f32 저장값을 넓혀 계산하는 value-only f64 브리지를 사용했으며, 보존된 별도 fp64 AD 호출은 호스트에 붙은 수반 실행이 아니다. 전체 타일 Jacobian, 호스트 역학·경계·강제력 미분, QNICE 물리 단위와 GK2A–RTTOV 비용 민감도는 확인 범위 밖이다.
