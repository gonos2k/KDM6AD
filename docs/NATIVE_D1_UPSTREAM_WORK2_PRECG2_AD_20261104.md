# 진입 work2·precg2 생산 경로를 D1→ProgB C++ 미분에 연결

[기존 C++ D1→ProgB 단계 검증](NATIVE_D1_PROGB_CPP_LOCAL_AD_20261104.md)은
`work2`·`precg2`·진입 `rhox`를 고정했다. 이번에는 같은 native
`(203,149,16)`, 20초 mp137 호출의 **진입 preamble 이전 QG·BRS**와
생산 결과를 추가 포착했다. 실제 C++ `compute_work2_venfac(P,T,DEN)`와
하나의 진입 `progb_param_torch(QG,BRS)`가 만든 `precg2`·`rhox`를
함께 D1에 전달한다. D1 뒤에는 별도의 ProgB 재슬로프를 실행한다.
[증거 패킷과 재생](../harness/evidence/native_d1_upstream_cpp_ad_2026-11-04/README.md)

## 같은 호출의 원시 값과 실행 계보

새 캡처 **9,516행**은 이전 **8,892행의 순서·자료형·원시 비트**를
보존하고 진입 입력 7개·생산 결과 9개를 39층에 더했다. 계측 off/on
종료 체크포인트는 동일 SHA-256이며 직전 변형의 결과와도 같다.
선택한 16층에서는 다음 값을 직접 기록했다.

| 진입 단계 | f64 값 |
| --- | ---: |
| ProgB 이전 QG / BRS | `5.4038067779247255e−5` / `6.004757288472314e−8` |
| 생산한 `work2` | `200.29441022254784` |
| 생산한 `precg2` | `24.35783384950257` |
| 생산한 D1 입력 `rhox` | `899.9209324078313` |

생산에 사용한 macOS/Torch 2.13.0 환경에서 독립 Python thermo/ProgB
함수는 `work2`, `cpm`, `xl`, `precg2`, BRS, `avtg`, `bvtg`를
**39층 모두 원시 비트로** 재현한다. Linux/Torch 2.8의 독립 Python
기준에서는 `work2`의 최대 차이가 39층 중 **4 f64 ULP**로 측정됐다.
이 항목만 4 ULP 이내로 비교하고, `cpm`, `xl`, `precg2`, BRS,
`avtg`, `bvtg`, 활성 `rhox`는 원시 비트 검사를 유지한다.
native 생산자→D1 전달과 저장된 실제 C++ 기준 출력의 원시 비트
검사는 그대로 유지한다. 진입 `rhox`는
활성인 15–23층에서 재현한다. 비활성 층의 지속 ProgB 이력은
현재 기록만으로 결정하지 않는다. 비활성 `precg2` 등의 숫자가 새로
계산한 값과 같아도 이전 PR 보유값의 생산 이력까지 증명한 것은 아니다.
진입 preamble의 출력과 D1이
소비한 `work2`·`precg2`·`rhox`도 각각 원시 비트가 같다.

격리 C++ 실행기는 이 native DSO 빌드에 기록된 **같은 정적 archive**를
연결한다. 실제 함수의 기준 출력 16개는 새 진입 생산량부터 D1
저장·후속 ProgB까지 native 포착값과 모두 원시 f64 비트가 같다.

## 상류 생산자를 포함한 조건부 접선

입력 방향은 D1 진입 QV 상대, T의 1 K 절대, 진입 QG 상대,
**재저장 전 BRS 상대**, 압력 P 상대다. QG와 BRS가 변하면 진입
ProgB의 `precg2`와 `rhox`를 **같은 계산에서 함께** 다시 만든다.
밀도와 건조 질량 기준 밀도, 기울기·절편 등 다른 입력은 고정한다.

| 방향 | `work2` JVP | 진입 `precg2` JVP | 후속 밀도 JVP |
| --- | ---: | ---: | ---: |
| T 절대 1 K | `−0.5376620814389188` | `0` | 반올림 규모 `+2.842170943040401e−14` |
| QG 상대 | `0` | `+5.684666630498753` | `+899.9209324078313` |
| 재저장 전 BRS 상대 | `0` | `−5.684666630498753` | `−899.9209324078315` |
| P 상대 | `+66.76479673103562` | `0` | 반올림 규모 `+1.4210854715202004e−14` |

압력 상대 방향에서는 소스식의 지수 `0.3333333`에 따라
`δwork2=0.3333333×work2`가 된다. T 방향의 `work2` 접선도
점성·확산·밀도 항에서 독립적으로 도출한 식과 일치한다. 상류 생산
경로가 들어가면서 D1 NR의 T 접선은 고정 `work2` 계산의
`+388.06856471664145`에서 `+386.8132657262213`으로 바뀐다.
고정 입력 계산에 없던 P 방향 D1 NR 접선은 `+155.8781711140534`다.
이는 선택한 수치 좌표의 조건부 민감도이며 물리적 입자수 수지의
판정은 아니다.
선택한 첫 미세물리 세부 단계에서는 바깥 입구 QV와 D1 QV가 같고,
기록된 `pre.cpm`도 이 QV에서 재계산한 값과 원시 비트가 같다.
그렇더라도 QV 방향은 D1 진입 단계의 조건부 접선이다. 전체 바깥
단계의 QV 미분에는 `entry_cpm` 전달과 앞선 상태·강제력 경로가 필요하다.

실제 C++ JVP와 독립 Python 생산자 JVP, 가중 VJP 내적, 표현된 입력
간격의 중앙차분을 대조한다. 생산 환경에서 모든 국소 차분 끝점의
출력 16개가 독립 Python 재생과 원시 비트로 같고, Linux/Torch 2.8의
차분 끝점에서는 최대 **1 ULP** 차이를 관측했다. 다른 백엔드에는
`work2` 의존 출력과 감마·지수 생산식의 진입 `precg2`만 1 ULP
이내로 허용한다. 그 밖의 진입 ProgB 출력은 원시 비트를 유지한다.
각 끝점에서 진입·후속
ProgB의 활성 내부 분기와 D1 융해 제한 분기를 검사한다. 최대 C++–Python JVP
절댓값 차이는 `1.1368683772161603e−13`이다. `max(1,|JVP|)`로
정규화한 최대 FD–JVP 잔차는 `1.8718900719759824e−5`다. QV·T·P의
극소 후속 밀도 반응은 상쇄·반올림 규모로 처리한다.
QV→후속 밀도 비교의 별도 절댓값 한도는 `2e−17`이다. 해당 JVP에
`1e−13`을 더하고 저장된 두 가중 내적과 해시까지 다시 계산한 시험
출력은 전체 재생 경로에서 거부한다. T·P의 상쇄 성분은 기준 출력
ULP의 `rhox` 0.25배, `avtg` 0.1배, `bvtg` 0.01배로 검사한다.
압력 방향의 이 세 극소 접선을 모두 0으로 바꿔도 허용 구간 안에
든다는 회귀시험을 남겼으므로 표의 작은 부호를 물리 신호로 해석하지 않는다.

QG 상대 반보폭 `10⁻⁴`는 진입과 후속 ProgB **두 곳 모두** 상한
900을 넘는 양의 끝점을 만든다. 진입 상한 임계 변화는
`8.786059899409143e−5`다. 이를 국소 JVP 합격 차분에 섞지 않고
별도 분기 전환으로 기록한다. [실행 결과](../harness/evidence/native_d1_upstream_cpp_ad_2026-11-04/results.json)

## 검증 범위

이 패킷은 포착된 진입 상태에서 시작하는 **조건부 f64 preamble→D1→
postmelt ProgB 단계 그래프**다. 실제 교란 호스트나 전체 subcycle을
다시 실행한 결과가 아니다. 비공개 archive·실행 파일은 해시와
영수증으로 연결하고, 공개 CI는 보존된 출력의 산술을 재생한다.
JVP 가중 내적은 16항 합산의 반올림 근거로 검사한다. VJP 저장
내적에 같은 수치 한도를 적용한 것은 이 고정 패킷의 일관성
검사이며 역전파 그래프 전체의 일반 오차 보증은 아니다.
실행별 기록에는 기존 네 C++ 오브젝트 해시가 있고, 별도 native 빌드
영수증에는 `progb.cpp.o`를 포함한 전체 오브젝트와 연결 archive·DSO
해시가 있다. 공개 패킷에서 비공개 오브젝트를 독립 재컴파일하지는 않는다.
운영 f32, 고정한 기울기·절편 및 다른 상위 생산자, 지속 진단의
비활성 이력, 전체 호스트·GK2A–RTTOV 미분과 QNICE 물리 단위는
남아 있다. `scientific_status: INCONCLUSIVE`와
`physical_unit_status: INCONCLUSIVE`를 유지한다.
