# D1 진입 ProgB의 `cmg`·`pidn0g` 생산 접선

## 실제 계산 위치

저장된 native `(203,149)` 열의 39층·20초 f64 호출에서 초기 17층 QG·BRS를 각각 또는 함께 교란한다. D1 전 entry `pre=preamble(...)`의 ProgB가 반환하고, 지속 배열과 병합된 `rhox`, `cmg`, `pidn0g`를 살아 있는 텐서로 기록한다. 이 중 `pidn0g`는 같은 entry preamble의 graupel slope가 소비한다. D1 이후의 `pre1`·`pre2` 재계산과 구분한다. [증거 패킷](../harness/evidence/native_d1_progb_pid_cpp_ad_2026-11-09/README.md)

선택한 활성 분기에서 실행식은 다음 순서다.

\[
cmg=(\pi\,rhox)/6,
\qquad
pidn0g=((cmg\cdot n0g)\cdot g1pdgmg)/g1pmg.
\]

이번 패킷은 실제 ProgB 매개변수의 f64 저장값과 활성 선택을 함께 보존한다. 따라서 매개변수를 임의의 정수 계수로 묶지 않고, 곱셈·나눗셈의 원래 순서로 값과 접선을 재검증한다. 매개변수 접선이 0인 선택 방향에서는

\[
D(cmg)=\frac{\pi}{6}D(rhox),
\qquad
D(pidn0g)=\frac{n0g\,g1pdgmg}{g1pmg}D(cmg).
\]

이는 같은 전체 C++ 그래프의 연쇄법칙 분해다. ProgB를 끈 독립적인 물리 실험의 효과는 아니다.

실행된 기준 매개변수는 `n0g=4,000,000`, `g1pdgmg=6.000000000000001`, `g1pmg=1`이다. 특히 `g1pdgmg`를 수학적 정수 6으로 치환하면 기준 `pidn0g`에서 **1 f64 ULP 차이**가 생긴다. 실제 저장값은 `rhox=899.9209324078313`, `cmg=471.19749834401995`, `pidn0g=11308739960.256481`이다.

| 초기 상대 교란 방향 | `D(rhox)` | `D(cmg)` | `D(pidn0g)` |
| --- | ---: | ---: | ---: |
| QG17 | `+664.5633528` | `+347.9645578` | `+8,351,149,388.2565` |
| BRS17 | `−664.5867466` | `−347.9768068` | `−8,351,443,362.7593` |
| 공동 | `−0.02339375` | `−0.01224894` | `−293,974.5027` |

공동 방향에서 `pidn0g` 접선이 작은 것은 두 단독 방향의 큰 반대 항이 거의 상쇄되기 때문이다. 이 값은 #564의 `pidn0g → rslope_g` 입력 항 `+1.5821029466×10⁻⁹`로, 이어 #563의 `gfac_melt` slope 경로 중 약 `+117.1103`으로 전달된다. 이는 같은 그래프의 대수적 연결이며 별도 과정 제거 실험은 아니다.

## 증거와 남은 범위

#564에서 확인한 D1 진입 QG·BRS→밀도 계산과 `pidn0g→rslope_g` 소비 경로 사이를 연결한다. 기준점과 공동 `±10⁻³` 끝점의 밀도·BRS는 이전 native 캡처와 원시 비트로 대조한다. 새 `cmg`와 `pidn0g`의 별도 native-host 생산자 캡처는 없으므로, 이 둘은 격리 C++ 실행의 실제 텐서·저장 연산과 독립 끝점 차분으로 검증한 범위다. 기존 단계·VJP·최종 출력의 보존도 확인한다.

허용한 열 개 끝점 쌍에서 `cmg` 출력차를 별도로 비교한다. 아홉 쌍은 신호 상대오차 `10⁻⁶`을 직접 충족한다. 공동 방향 `h=10⁻⁶` 한 쌍은 상대 잔차가 `2.868×10⁻⁶`이지만 절대 잔차는 약 `1.24` 출력 ULP여서 선언된 4 ULP 바닥으로 수용한다. 한쪽 차분 두 건에도 같은 바닥을 적용한다. 기존 `rhox`·`pidn0g` 차분은 부모 패킷에서 검사하므로 중복된 새 독립 신호로 집계하지 않는다.

상류 native 17층의 밀도 상한 교차와 이번 native 16층 entry 밀도 경계는 별도 계산 노드로 분류한다. 다른 선택 분기, 비활성 ProgB의 이전 값 유지, 융해 적용량 (A)의 원률·제한식, 운영 f32, 물리 단위·과정별 수지, 전체 호스트와 GK2A–RTTOV 비용 미분은 남아 있다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`다.
