# 실제 호스트 타일의 f32 C ABI 호출과 재생

기존 5 km native 사례에서 `mp_physics=137`을 한 MPI rank·한 thread로 20초 실행해 **실제 호스트 래퍼가 넘긴 전체 f32 타일 호출**을 비공개로 기록했다. 복사한 호스트 실행 파일에 격리 proxy를 연결했고, proxy는 설치된 `kdm6_step_c` 공유 라이브러리로 호출을 전달했다. 운영 설치·원본 실행 파일·원본 사례는 변경하지 않았다. [공개 영수증 패킷](../harness/evidence/native_host_tile_abi_2026-11-11/README.md)

실제 두 번째 ABI 호출은 `232×39×139`, `dt=20`, `value_only=1`, `ncmin_land=ncmin_sea=10`이었다. WRF의 두 번째 바깥 타일을 `specified=.true., spec_zone=1`에 따라 잘라낸 내부 범위 `i=2..233, j=143..281`과 크기가 맞는다. 따라서 native `(203,149)`는 타일 안의 0기준 `(201,6)`, runtime batch index **27945**에 대응한다. ABI에는 타일 원점이나 내부 `mstepmax`가 직접 전달되지 않으므로, 인덱스 연결은 호스트 로그·소스·배열 크기를 함께 사용한 것이다.

비공개 전체 타일 입력을 **같은 설치 DSO**에 다시 전달한 결과, 12개 상태 필드·강수 증가량 세 개·RHOG의 모든 출력 원시 f32 단어가 일치했다. 목표 열만 B=1로 따로 재생한 출력도 타일 안 해당 열과 일치했지만, 내부 substep 일정이 동일하다고 판정하지는 않는다. 별도 proxy on/off 호스트 실행에서는 실제 저장된 **00:00:00과 00:00:20** 두 프레임의 forecast 변수 254개와 energy 변수 5개가 각 프레임에서 모두 원시 비트로 일치했다. ocean·precipitation 파일은 저장 프레임이 0개였으므로 검사 건수에 넣지 않았다.

호스트 입력을 앞선 #556·#578의 저장 입력과 동일하다고 연결할 수는 없다. #556 입력은 **00:00:40 체크포인트에서 시작한 격리 f64 계산**이고, 이번 호스트 호출은 **00:00:00에서 시작한 설치 f32 계산**이다. 캡처 타일 어디에서도 #556의 16×39 전체 입력 서명이 정확히 일치하지 않았다. 따라서 #578의 활성화 경계 위치나 접선을 이번 호스트 시각으로 이월하지 않는다.

전체 타일 원본 146,405,972바이트(압축 45,533,165바이트), NetCDF 프레임과 바이너리는 비공개 `host/research_evidence/`에만 보존한다. 공개 패킷에는 SHA 영수증, 선택 열의 세 층 원시 단어, 비교 결과와 재생 코드를 넣었다. **공개 CI는 영수증·요약의 일관성만 검사**한다. `PRIVATE_TILE_PATH`와 `PRIVATE_DSO_PATH`가 있는 동일 작업 공간에서만 선택 열 원시값을 타일에서 다시 추출하고 전체 ABI 출력을 재계산할 수 있다. 공개 자료만으로 호스트 실행 사실이나 없는 바이너리·NetCDF의 해시를 독립 인증했다고 주장하지 않는다.

첫 타일 입력만 기록한 탐색 실행과 재귀적인 `DYLD_INSERT_LIBRARIES` 시도는 합격 증거에서 제외했다. 실제 비교에 쓰인 `strict_bitwise_nc.py` 소스 해시는 비교 **후** 확인돼 실행 시점에 고정된 해시로 표시하지 않는다. 첫 유효 proxy 실행에는 live 로더 관측이 있으나 짝지은 proxy-on 실행의 로더를 별도 관측하지는 않았다. proxy 소스의 공개 사본은 로컬 경로를 제거한 설명용 파일이며 실행 파일의 원시 바이트와 같지 않다.

이번 결과는 선택한 타일·시각의 f32 순전파 ABI 연결이다. `mp_physics=37`과의 순전파 일치, land/sea ncmin 차이, 내부 substep 일정, 질량·수농도·체적 수지, 호스트 AD, native 관측 입력의 center/interface pressure 및 GK2A–RTTOV 비용 민감도는 별도 과제다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`로 유지한다.
