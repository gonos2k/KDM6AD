# 동일 호출 일정과 합성 완료 판정의 경계

이 묶음은 #590 검토에서 재현된 **같은 호출의 일정 기록 모순**과 **완료 표식 공개 후 중단** P2 두 건을 고친다. 고정된 `(203,149)` 열의 45개 입력·100회·900초 계획, 기존 물리 구현과 원자료는 변경하지 않는다. 실제 계측 DSO·ABI 생산자·WRF 실행은 아직 없으며, 모든 새 호출은 저장소의 고정 **합성 스텁**이다.

## 조건 자산과 일정 value record의 일치

`receipt_schema.py`는 #586 기준의 호출별 Boolean 1,170개·일정 195개 키를 검증하면서, `record_kind=value`이고 같은 정규화 키가 일정 목록에 있으면 **같은 capture-on 호출의 `schedule_words` 원시 f64 단어**와 직접 대조한다. `live_tangent`는 원래 일정값과 비교하지 않는다. 이 검사는 FD adapter가 조건 자산만 보고 다른 일정 변화를 놓치기 전에 실행된다.

상측 PII의 선택 끝점 `upper:pii:1e-06:+1`과 NC `+2h`에 `runtime_full_meta/loops` value record `2.0`, 조건 자산 `1.0`을 넣고 모든 자산을 재해시한 합성 반례는 이제 거부된다. 조건도 `2.0`으로 맞추면 FD 입력에 일정 교차가 남아 해당 비교가 `BRANCH_CROSSING`으로 분류된다. 이는 **제출된 두 자료의 내부 일치**이며, 실제 외부 바이너리의 일정 진위를 인증하지 않는다.

## 완료 후보와 감독 확인을 분리

`execute_budget.py`가 파일로 남기는 영수증·`completion.json`은 이제 `SYNTHETIC_CANDIDATE_UNVERIFIED` / `CANDIDATE_NOT_SUFFICIENT`다. **후보 표식만으로 완료를 받아들이지 않는다.** `synthetic_supervisor.py`는 예산 실행기를 별도 자식으로 실행한 뒤 실제 `waitpid`의 정상 종료 코드와 부모가 관측한 전체 경과시간을 확인한다. 자식은 `scheduler.run()`이 **반환한 뒤에만** 영수증·후보 SHA를 묶은 반환 토큰을 기록한다. 감독자는 토큰, 종료 코드 0, 예산 이내 전체 시간을 모두 확인한 경우에만 별도 `supervisor_witness.json`을 공개한다. 영수증 소비자는 영수증·후보·반환 토큰·감독 확인의 바이트와 소스·계획·종료 코드·시간을 함께 대조한다. 후보 공개 직후 `os._exit(0)`으로 조기 종료해도 반환 토큰이 없어 거부된다.

1초 합성 예산에서 후보 표식의 공개를 지연시켜 **전체 1.6초**가 되게 한 뒤 프로세스를 중단한 반례는 후보 파일이 남아도 감독 확인 파일이 없어 거부된다. 정상 종료 코드 0이어도 부모 관측 시간이 1초를 넘으면 확인 파일은 없다. 이 절차는 완료 후보 **공개 뒤의 추가 검사를 기다리는 구조가 아니다**. 감독자가 확인 파일을 공개하기 전 정상 종료와 시간 판정이 끝난다. 감독 확인 파일의 작성시간은 자식 예산 밖의 감독 작업이며, 감독자 자신이 멈추면 확인 파일을 내지 않는다. 이 합성 감독자는 동기식 `waitpid`를 사용하므로 자식이 무한 대기하면 별도 외부 watchdog이 필요하다.

감독 확인은 현재도 **서명되지 않은, 제출자가 제공한 합성 자료**다. 검증기가 정상 종료라고 적힌 파일의 내부 관계를 확인하더라도 독립 실행·로더·DSO 출처까지 증명하지 않으며 결과는 `NOT_ELIGIBLE_UNVERIFIED_PROVENANCE`다. 기본 생산 실행 경로는 계속 차단된다.

## 조건 검증의 재사용과 아직 막힌 계측

`fd_input_adapter.adapt_many()`는 요청한 출력 인덱스 전체에 대해 같은 영수증·자산 스냅샷을 한 번 검증하고 45개 호출별 조건 자료를 한 번 조립한 뒤, 각 출력에 `fd_gate.evaluate()`의 입력·수치 검사를 별도로 적용한다. 서로 다른 출력의 결과는 독립 객체로 반환하고 함수 호출 사이에 검증 결과를 캐시하지 않는다. 이 구조는 468개 출력마다 100개 호출과 조건 자산을 다시 읽는 반복 비용을 줄이기 위한 것이다. 합성 자료의 **3개 출력**에서 개별 반복 2.436초와 배치 0.893초의 결과가 정확히 같았고, **468개 배치 한 번은 47.253초**였다. 같은 환경에서 468번의 개별 호출을 추가 실행한 대조는 없으며, CI의 보장된 절감률도 아니다.

[소스 필드 계약](../harness/evidence/native_host_preflight_2026-11-12/field_contract.json)의 **28개 측정 항목·19개 제안 마스크**는 계속 `BLOCKED`다. 현재 조건 adapter는 #586에 있던 키만 수용한다. 실제 NC·PII·침강·열·BG 중간값과 살아 있는 접선을 기록할 때는 새 마스크·outer loop·층/열 identity, 계측 소스, 격리 빌드, `EXECUTION_READY` 후속 계획과 실제 ABI 생산자를 먼저 버전으로 고정해야 한다. 이번 수정만으로 `fd_gate_ready`를 참으로 만들거나 #586/#587의 출력에 새 미분 합격을 소급 부여하지 않는다. `scientific_status`와 `physical_unit_status`는 계속 `INCONCLUSIVE`다.
