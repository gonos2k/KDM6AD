# D1 진입 싸락우박 slope에서 `coeres_g`까지의 값·접선 연결

저장된 native `(203,149)` 열의 39층·20초 f64 호출에서 초기 17층 QG·BRS를 각각 또는 함께 교란한다. D1 이전의 **진입** `pre=preamble(...)`에서 싸락우박 slope의 실제 입력·출력을 살아 있는 C++ 텐서로 보존하고, D1 융해 계산이 소비하는 값과 접선을 대조한다. 이는 D1 뒤에 재계산하는 `pre1`·`pre2`의 slope가 아니다. [증거 패킷](../harness/evidence/native_d1_coeres_upstream_cpp_ad_2026-11-10/README.md)

선택된 비마스크 분기에서 `r=rslope_g`, `b=bvtg`라 놓으면 생산식은 다음과 같다.

\[
rslope2_g=r\,r,\qquad rslopeb_g=\operatorname{safe\_pow}(r,b),\qquad
rslopemu_g=\operatorname{safe\_pow}(r,MUG).
\]

실제 분기 조건은 `QG<=QCRMIN`이며, 이번 선택 사례에서는 거짓이다. `MUG=0`이어서 기록된 `rslopemu_g=1`이고 세 선택 방향의 접선은 0이다. 이를 다른 상수·분기나 임의 입력 방향의 관측 결과로 확대하지 않는다. 실제 C++ 생산값에서 D1 소비값으로의 전달은 원시 비트로 검사하고, 독립 Python 거듭제곱 계산의 마지막 ULP 차이는 별도 기준으로 판정한다.

새 `coeres_values()`의 독립 Python `coeres_g` 진단은 최대 **4 ULP** 차이를 허용한다. 이는 부분 진단의 기준이다. 전체 `replay()`는 뒤이어 기존 D1 융해 생산식을 별도로 재계산하며, 그 `coeres_g`와 후속 중간값이 저장된 C++ 값과 **원시 비트로 일치**해야 한다. 선택 제곱근을 1 ULP 바꾼 모의 계산은 부분 진단을 통과해도 전체 재생의 `D1 melt source-order` 검사에서 거부된다. 따라서 4 ULP 허용 테스트만으로 전체 제곱근·libm 경로의 이식성이 확인됐다고 해석하지 않는다. 생산자에서 소비자로의 원시 비트 전달 기준도 유지한다.

D1 소비식은 다음 연산 순서를 갖는다.

\[
coeres_g=\left[rslope2_g\sqrt{\max(rslope_g\,rslopeb_g,qcrmin)}\right]_{f64}
\,rslopemu_g,
\]

이어 `pgmlt_term2=[(precg2\,n0go)\,work2]_{f64}\,coeres_g`가 융해 원률에 들어간다. 선택 내부 분기에서 `coeres_g`의 공동 QG17+BRS17 방향 접선은 약 `5.987893947838642×10⁻¹¹`이고, 실제 저장된 입력에 대한 연쇄법칙 항은 다음과 같다.

| `D(coeres_g)` 항 | 공동 방향 기여 |
| --- | ---: |
| `rslope2_g` | `+4.334504571482948×10⁻¹¹` |
| 제곱근 안의 `rslope_g` | `+1.083626142870737×10⁻¹¹` |
| 제곱근 안의 `rslopeb_g` | `+5.697632334849566×10⁻¹²` |
| `rslopemu_g` | `0` |

이에 따라 `pgmlt_term2`의 `coeres_g` 항은 약 `+1.1685346214`, 앞서 검증한 `precg2` 항은 약 `−0.0000122832`이며, 전체 접선 `+1.1685223382`와 맞는다. 이 항들은 같은 상류 그래프의 조건부 연쇄법칙 분해이며 물리과정을 독립적으로 제거한 효과가 아니다.

기준점과 공동 방향 `±10⁻³` 끝점에서는 상류 ProgB 경계의 `bvtg`, D1 **소비자** 경계의 `qg`·`rslope_g`·`rslope2_g`·`rslopeb_g`·`rslopemu_g`·`qcrmin`·`coeres_g`를 native 캡처와 대조한다. 세 사례에 8개 필드씩이며, 별도의 native slope 생산자 캡처가 있다는 뜻은 아니다. 다른 끝점은 격리된 C++ 실행값으로 검증한다. 선택한 비마스크·비제한 분기 밖의 동률점, 활성 제한, 열역학 QV·T 방향, 운영 f32, 물리 단위·적용 예산, 전체 호스트 AD 및 GK2A–RTTOV 비용 미분은 남아 있다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`다.

계측한 `rslopegbmax`는 이번 비마스크 분기에서 사용되지 않는 cap 입력이다. 현재 재생기는 이 값이 유한한 양수인지 확인하지만, 그 생산식이나 마스크 분기의 실제 선택값까지 독립적으로 재구성하지 않는다. 따라서 재해시한 이 입력 하나의 변경이 산술 override 검사를 통과할 수 있다. 원본 자료 자체는 manifest 해시로 고정된다.

저장된 25개 사례에서 `rslope2_g` 제곱과 D1로의 여섯 피연산자 전달은 원시 비트로 일치한다. 독립 Python 거듭제곱으로 계산한 `rslopeb_g`와 소스 순서로 계산한 `coeres_g`도 이번 환경에서는 각각 최대 **0 ULP** 차이였으며, 부분 진단의 ULP 한도는 별도 검사한다. 세 초기 방향에는 방향별 수치 단계 접선 **322개**가 보존됐다. 상류 밀도 상한 교차를 제외한 10개 입력 쌍에서 새 slope 출력 두 개의 중앙차분은 **20건**, 최대 신호 상대오차 `1.2212×10⁻⁷`이다. 이미 부모에서 확인한 `coeres_g`의 차분 10건은 이번 경로에 맞춰 재검사했으며 최대 잔차는 `1.1102×10⁻⁸`이다. `rslopemu_g=1`의 선택 방향 접선 0은 상수 지수 분기에서 확인하며, 이를 분해 가능한 비영 차분 신호로 세지 않는다.
