# 동일 호스트 열 공통 계측의 실행 전 고정 자료

이 묶음은 #587의 [저장 출력 분석](../harness/evidence/native_host_batch4_analysis_2026-11-12/README.md)과 [공통 계측 계획](NATIVE_HOST_BATCH4_COMMON_CAPTURE_20261112.md)을 실제 실행 전에 검토 가능한 자료로 고정한다. **새 KDM·WRF·RTTOV 호출은 수행하지 않았다.** 원래 native `(203,149)` 열, 39층, 20초, Legacy f64 B=1 값/AD 실험의 입력 계보를 유지한다.

## NC 세 값의 의미

기존 `nc_second_forward_rows`의 `fd`는 중심에서의 **3점 전진차분**이다. 이번에는 원시 단어 `y_0,y_h,y_{2h}`에서 아래 세 값을 각각 저장했다.

\[
D_{0,h}=\frac{y_h-y_0}{h},\qquad
D_{h,2h}=\frac{y_{2h}-y_h}{h},\qquad
D_{\mathrm{3pt}}=\frac{-3y_0+4y_h-y_{2h}}{2h}.
\]

`center_to_plus_fd`, `plus_to_plus2_fd`, `three_point_forward_fd`가 이 순서에 대응한다. 이전 `fd`는 세 번째 값의 별칭으로 보존했다. 일반 출력별 FD와 NC 3점 FD 모두 **부호 있는 `FD−JVP`**를 새 필드로 저장하고 기존 절대오차도 유지한다. baseline NC16, `h=10⁻⁴`에서는 세 값이 각각 약 `1.29647×10¹⁰`, `0`, `1.94470×10¹⁰`이다. 이는 선언된 `10⁸` NC seed로 정규화한 보폭 기준의 수치이며 물리 단위가 승인된 편미분이 아니다. `y_h=y_{2h}≠y_0`만으로 경계 불연속이나 AD 오류를 확정하지 않는다.

## 45개 입력과 호출 예산

[공개 preflight 패킷](../harness/evidence/native_host_preflight_2026-11-12/README.md)의 `plan.json.gz` SHA-256은 `4d6a935c9d83d987a8a2149d58699b2812af565785d20c599cf9f49f05846b8a`다. #580의 624개 f32 단어를 정확히 f64로 확장하고 #586의 세 TH16 중심과 방향 seed를 적용해 **45개 고유 입력의 전체 624단어**를 고정했다. 모든 입력은 #586에서 이미 **선언된 입력**과 일치한다. 그중 상측 PII `10⁻⁶`는 #586의 **실행 출력이 없는 새 관측 대상**이며 입력 일치만으로 출력 일치를 주장하지 않는다.

| 예정 목록 | 입력 수 |
| --- | ---: |
| 세 중심 | 3 |
| NC `+h,+2h`, 세 중심×세 보폭 | 18 |
| PII `−h,+h`, 하측·상측×세 보폭 | 12 |
| TH·QV `−h,+h`, 세 중심×`10⁻⁵` | 12 |
| **합계** | **45** |

각 입력에 capture off/on 값 호출 90회, 세 중심 joint 그래프 3회, 선택적 설치본 값 대조 최대 7회로 **100회·900초** 상한을 명시했다. 실제 계측 DSO의 SHA-256·컴파일러·의존성·실행 영수증이 아직 없고 `execution_receipt=null`이다. preflight 검증기는 새 DSO SHA가 비어 있는 상태의 실행을 명시적으로 거부한다. 계획을 Git 커밋으로 먼저 고정한 뒤의 미래 호출이 그 커밋·계획 해시를 인용해야 사전 선언의 시점 근거가 생긴다. 계획 JSON의 자기 진술만으로 시간 순서를 증명하지 않는다.

계획의 `SOURCE_PINS`는 **이번 빌드 준비 시점의 live 공개 소스 freshness 검사**다. 이후 해당 소스가 바뀌면 현재 계획의 재생 검사가 실패하므로 새로운 계획과 빌드 출처를 만들어야 한다. 원래 실행 증거의 의미를 새 소스에 자동으로 옮겨 붙이는 방식으로 사용하지 않는다.

## 필드 목록과 판정기

`field_inventory.json`은 기존 **51개 stage·505개 stage/field 조합**에 대해 NC=0, PII, 실제 rate–cap 동률, 침강 적용량, 명명 과정, 같은 호출 물 수지, 열·BG의 일곱 묶음을 지정한다. 각 묶음의 값·**살아 있는 AD 접선**·마스크가 필요하다고 구분했고, 기존 capture에 없는 정확한 레이블도 보존했다. 레이블 부재는 같은 물리량이 다른 이름이나 미계측 경로에 없다는 증명은 아니다. 실제 적용 departure/arrival, 바닥 유출, f64 총강수, cleanup 전후 상태와 단위 측도가 없는 상태에서 물리 수지를 판정하지 않는다.

반복 substep의 값을 덮어쓰지 않도록 미래 기록의 식별자를 **입력·mode·runtime 호출·one-step 호출·substep·열·층·stage·field·record 종류·미분 종류·방향/seed·VJP cotangent·event 순번**으로 고정했다. `k_zero=0`은 native 최상층 39이며 `native_level_bottom_first=39−k_zero`를 검사한다. 계획에 없는 입력, 값 전용 호출의 live 접선, 중심이 아닌 입력의 그래프 기록, 같은 식별자의 중복을 거부한다. 같은 stage/field가 실제로 반복되면 event 순번을 0부터 연속으로 기록하고, 서로 다른 방향이나 cotangent는 별도 식별한다. 필수 피연산자가 비활성 분기 때문에 없을 때도 누락 사유를 명시해야 한다. **현재 검증기는 식별자만 검사하며 실제 seed 내용·수치 payload·필수 필드의 전체 존재·비활성 누락 사유는 미래 실행 재생기의 과제**다. 값 전용 CSV와 살아 있는 그래프 텐서의 수명·검증도 별개다.

`fd_gate.py`는 [다음 실행용 수치 기준](NATIVE_HOST_OUTPUT_FD_GATE_V1_20261112.md)의 16 출력 ULP 해상도, 두 안정 보폭, 실제 성분별 표현 방향과 `10⁻⁶` 상대 잔차를 **합성 자료에서** 실행한다. 계획의 가장 작은 두 보폭만 국소 판정에 사용하고 큰 보폭의 교차는 진단으로 보존한다. 상측 PII에서는 `10⁻⁶`·`10⁻⁵`가 판정용, `10⁻⁴`가 진단용이다. 정상 모드는 위의 고정 계획 해시와 중심·방향·끝점 624단어를 요구한다. 교차, 방향 퇴화, 수치 불일치, 미해상, 반올림 제한을 따로 기록하고 `+h→+2h` 변화도 보존한다. 한 보폭만으로 국소 일치 태그를 주지 않는다.

현재 판정기는 호출자가 제공한 출력·JVP·마스크 영수증의 내부 일치를 검사할 뿐 **독립 실행 출처를 확인하지 않는다.** 따라서 합성 자료가 수치식을 만족해도 결과는 `UNVERIFIED_EXECUTION_RECEIPTS`와 `NOT_ELIGIBLE`이다. #586/#587의 저장 사례에 새 합격 수를 소급 부여하지 않는다. 미래 실행의 DSO·asset 해시, 실제 호출 순서, 모든 계획 입력의 완료/실패 기록이 추가돼야 채택 가능하다.

## 새 빌드에서 확인해야 할 소스 경계

현재 소스 검토에서 NC=0의 가능한 분기 후보는 `runtime.cpp`의 입구 수치 제한, `coordinator.cpp`의 post-melt·post-freeze NC 재계산과 마지막 DSD 제한이다. 기존 값 CSV에는 일부 `fd_snap_a/b` 전후 NC가 있으나 QC·density·원시/제한 기울기·선택 마스크가 모두 있지는 않다. **후보 위치이지 평탄 출력의 검증된 원인은 아니다.** 활성화 피연산자 값 기록은 이미 있지만 이전 `stage.field` 중심의 그래프 기록은 반복 substep을 덮어쓸 수 있으므로, 위의 완전한 식별자로 실제 살아 있는 텐서를 보존해야 한다.

침강에서는 각 종의 후보 이동량과 **독립적으로 제한된 실제 출발량·도착량**, projection 잔차, 바닥 유출을 같은 substep에서 기록해야 한다. 두 적용량이 자동으로 같다고 가정하지 않는다. 여섯 물 필드의 수치 수지는 승인된 `rho·delz` 측도와 적용 export를 받은 뒤 계산한다. `kdm6_step_ad_c`와 joint state+forcing ABI는 f64 **상태 468개만** 포장해 돌려주며 총강수·RHOG를 packed AD 출력으로 추가하지 않는다. 총강수와 그 민감도가 필요하면 `FnResult`의 실제 텐서를 이용한 별도 테스트 전용 관측 경로로 구현하고 값 전용 sidecar와 그래프 접선을 구분한다.

명명 과정은 후보 rate→제한 후 실제 적용량→출발/도착 상태→다음 소비 입력을 순서대로 기록한다. 활성화의 매끄러운 적용 분기에서는 수농도 `A=ncact·dt`가 NCCN에서 NC로 옮겨지지만, 완전 증발 반환과 reservoir 하한/상한은 별도 항이다. 질량 `M=pcact·dt`와 잠열 온도 반응도 적용 게이트 안에서만 해석한다. `BG=brs`는 graupel **체적** 좌표이므로 QG 질량 수지와 곧바로 등치하지 않는다. 실제 적용량·층 가중치의 JVP는 연쇄·곱 규칙으로 도출하고, VJP 내적과 분기 내부의 독립 방향차분을 함께 검사한다. 동률에서는 별도 연산자 시험의 자동미분 정책을 전체 물리 그래프의 도함수로 소급하지 않는다.

이 단계의 `scientific_status`와 `physical_unit_status`는 모두 `INCONCLUSIVE`다. 다음 묶음에서 새 계측 빌드의 출력 비침습성과 살아 있는 피연산자 접선을 확인한 뒤에야 NC·PII 원인 및 적용 수지 검증을 진행한다.
