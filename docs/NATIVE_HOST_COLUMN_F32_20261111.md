# 실제 호스트 호출의 선택 열 전체 f32 입력

앞선 [#579 호스트 타일 영수증](../harness/evidence/native_host_tile_abi_2026-11-11/README.md)의 비공개 전체 타일에서 native `(203,149)` 열을 39층 모두 추출했다. 이번 [공개 패킷](../harness/evidence/native_host_column_f32_2026-11-11/README.md)은 호스트가 실제 두 번째 `kdm6_step_c` 호출에 넘긴 **상태 12개·forcing 4개 ×39층 = 입력 624개 f32 단어**, XLAND, **상태 출력 468개·강수 3개·RHOG 39개 = 출력 510개 단어**를 보존한다. 전체 타일·NetCDF·바이너리는 계속 비공개다.

타일의 내부 범위 `i=2..233, j=143..281`에서 목표 열은 0기준 `(201,6)`, runtime 배치 인덱스 `201×139+6=27945`다. 원시 Fortran 배열의 위치는 `(j×39+k)×232+i`이므로 배치 인덱스와 다르다. 공개 재생은 입력·출력 624+510개 전체 단어의 형식·유한성·순서와 #579의 세 층 공개 표본을 대조한다. 전체 열이 **호스트 타일에서 추출됐다는 사실 자체**는 공개 요약만으로 독립 인증할 수 없고 비공개 타일 재생이 필요하다.

이 입력을 설치된 표준 f32 C ABI에 **B=1로 다시 넣은 실제 출력 510개**는 타일 속 해당 열과 원시 비트로 모두 일치했다. 계측 DSO의 캡처 off/on 출력도 각각 설치 DSO와 510개 모두 같다. 비공개 타일과 정확한 설치 DSO를 제공하는 선택 검사는 전체 타일 출력에 더해 B=1 출력 510개를 새로 계산해 비교한다. 계측 DSO 자체는 이 선택 검사에서 재실행하지 않는다. 이는 선택한 호출의 **출력 관측 일치**이며 내부 substep 일정의 동등성 증명은 아니다.

별도 B=1 캡처는 native 16층의 활성화 단계 33개 값을 기록했다. `sw_percent≈0.82243681`, 실제 pow 피연산자 `≈1.38139153>1`, 선택 비율 `1`, `ncact_raw`와 NCCN rate 상한은 둘 다 `5,000,000`이다. 공개 재생은 CSV의 원시 f32 단어와 소스 연산 순서에 따른 최소 연산·게이트·NC/NCCN 갱신을 확인한다. 독립 Python pow 계산은 **4 f32 ULP 이내의 진단**이며 실제 C++ 피연산자와 최소 연산 결과의 전달은 기록된 원시 단어로 검사한다. `cloud_complete_evap`은 하류 산술에 쓰는 **기록된 마스크**이고 그 상류 생성식은 독립 재계산하지 않았다. **이 단계값은 호스트 타일 내부의 직접 계측값이 아니라 호스트 입력을 별도 B=1로 재생한 결과**다. 값 동률에서의 미분 규칙은 확인하지 않는다.

같은 입력의 TH16 f32 단어 공간을 좁게 탐색하다가 활성화 상한을 양쪽에서 포괄하기 전에 **raw rate 대 NCCN cap의 분기 상태가 바뀌어** 탐색을 중단했다. QV 방향 탐색은 수행하지 않았다. 따라서 이번 입력의 새 활성화 경계 위치를 보고하지 않는다.

#556·#578 입력은 00:00:40 체크포인트의 역사적 격리 f64 계산에서 나왔고, 이번 입력은 00:00:00→00:00:20 설치 f32 호스트 호출에서 나왔다. 같은 수평 좌표라도 두 입력을 동일 상태로 다루지 않는다. 이번 결과는 실제 호스트 선택 열에서 B=1 f32 값·단계 계산을 연결하지만, 호스트 전체 타일의 내부 일정, f32 AD, mp37 parity, 물리 단위·과정 수지, native 관측 연산자의 center/interface pressure 및 GK2A–RTTOV 비용 민감도를 완료하지 않는다. `scientific_status`와 `physical_unit_status`는 `INCONCLUSIVE`다.
