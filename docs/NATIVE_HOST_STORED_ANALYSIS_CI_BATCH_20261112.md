# 선택 열 저장 자료 분석과 Oracle CI 실행 묶음

이 묶음은 #583의 **저장된 값·JVP·차분과 공개 CI 로그**만 사용한다. 새 KDM·호스트·RTTOV 호출은 없다. [재생 자료](../harness/evidence/native_host_analysis_batch_2026-11-12/results.json)는 입력 계보·원본 해시를 고정하고 01·07·19의 분석을 다시 계산한다. 20·21·22는 같은 PR에서 필수 Oracle 작업의 실행 방식을 바꾸되 검사 목록과 최종 필수 상태를 보존한다. 다음 비싼 실행의 공통 자료 계획은 [별도 문서](NATIVE_HOST_COLUMN_SHARED_CAPTURE_PLAN_20261112.md)에 정리했다.

## 01 — 저장된 출력 468개 전체의 TH16 방향 차분

#583의 f64 양쪽 내부점, 각 `h=10⁻³,10⁻⁴,10⁻⁵ K`에 대해 **2×3×468 = 2,808개** 출력 성분을 다시 계산했다. 각 행에는 필드·native 층·원시 단어, 표현된 실제 입력 간격, 중앙차분·JVP, 도함수 절대오차, 출력 변화의 잔차, 중심/양끝의 최대 f64 출력 ULP 기준 잔차가 있다. `harness/verify_state_forcing_ad.py`가 선언한 필드별 수치 스케일 `TH=1`, 수상체·QV=`10⁻³`, NCCN/NC=`10⁸`, NI/NR=`10⁶`, BG=`10⁻⁶`도 고정 소스 사본으로 확인해, 도함수 절대오차와 출력 잔차를 각 스케일로 나눈 값을 보존했다. 이는 **미분 검증용 수치 스케일이지 물리 단위 승인이나 불확도 추정이 아니다**. 별도로 값 크기에 따른 정규화 분모 `max(|중심 출력|, |양끝 출력|, 해당 필드 수치 좌표 1)`을 사용했으며, 마지막 1도 물리적 공통 단위가 아니다.

| 내부점 | 보폭별 다른 출력 단어 | 같은 출력 단어·JVP=0 | `h=10⁻⁵` 최대 필드 스케일 출력 잔차 | 같은 보폭의 최대 출력 ULP 잔차 |
| --- | ---: | ---: | ---: | ---: |
| 비율=1 쪽 | 각 6개 | 각 462개 | TH16 **2.9276×10⁻¹⁴** | NR16 **105.70 ULP** |
| 비율<1 쪽 | 각 7개 | 각 461개 | NC16 **4.5056×10⁻¹³** | NC16 **3,023.67 ULP** |

가장 작은 보폭에서 다른 단어를 보인 것은 두 쪽 모두 16층의 TH/QV/QC/QR/QS/NR이고, 비율 `<1` 쪽에는 NC16이 추가된다. 같은 단어인 462·461개는 **해상되지 않은 신호**로 분류한다. 이 중 기록된 JVP가 0이라는 사실은 정확한 물리적 무감도를 입증하지 않는다. 큰 출력 ULP 잔차를 “반올림 몇 ULP 이내”라고 표현하지 않는다. 이 비교는 **초기 TH16 한 방향의 전체 출력 검사**이지 468×468 Jacobian 검증이나 모든 과정 분기의 안정성 검사가 아니다.

## 07 — 운영 f32와 f64 DA 기준 출력의 위치별 차이

동일한 호스트 선택 열의 624개 f32 원시 입력이 f64에서 정확히 표현되고, f32 B=1 출력이 공개된 타일 선택 출력과 468개 모두 같은 것을 다시 확인했다. 그 뒤 f64 기준 출력을 f32로 반올림한 단어와 운영 f32 단어를 비교했다. **367개 일치, 101개 불일치**다.

| 필드 | TH | QV | QC | QR | QI | QS | QG | NCCN | NC | NI | NR | BG |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 불일치 단어 | 9 | 19 | 20 | 13 | 5 | 5 | 5 | 1 | 11 | 7 | 2 | 4 |

활성화 대상 16층에는 6개, 인접한 15·17층에는 합계 7개, 나머지 층에는 **88개**가 있다. 가장 큰 반올림 후 단어 차이는 **NC12의 88,245 f32 ULP**다. 따라서 차이가 활성화 대상 층에만 국한되지 않는다. 원시 f32/f64 단어, f32 반올림 후의 부호 있는 ULP 거리와 값 차이를 행별로 보존했다. 이 분류만으로 어느 단계의 정밀도·분기·상수가 차이를 만들었는지는 확정하지 않는다.

## 20·21·22 — 한 필수 작업 안에서 재생 범위 유지

기존 필수 체크 이름 **`oracle pytest (f64 reference)`**와 Oracle/native 기본 검사, 일반·`-O` 두 모드는 유지한다. [외부 suite 목록](../harness/oracle_evidence_suites.json)은 기존 49개를 고정된 기준 집합으로 보존하고 이 분석 패킷을 50번째로 등록한다. [실행기](../harness/run_oracle_evidence_suites.py)는 suite마다 별도의 Python 프로세스를 시작하며, 모드별 과거 시간을 힌트로 길이가 긴 suite부터 두 작업자에게 배분한다. 힌트는 **실행 순서에만** 영향을 주고, 완료 판정이나 누락 허용에는 영향을 주지 않는다. 한 작업 안에서 실행하므로 Torch 설치를 여러 CI job에 반복하지 않는다.

목록 검사는 중복·없는 경로·경로 이탈·0개 테스트·기존 필수 suite 누락을 거부한다. 현재 테스트 디렉터리 82곳을 **활성 50곳과 명시적으로 제외한 역사적 32곳**으로 분류하며, 나중에 새 테스트 디렉터리가 어느 쪽에도 등록되지 않으면 실패한다. 실행기는 모든 자식의 종료 코드·신호·시간초과·skip 수와 이유, 완료/미실행 상태를 기록한다. 한 suite라도 실패·취소·누락이면 기존 필수 체크가 실패한다. 일반·최적화 모드가 같은 목록을 사용하며 자식 Python에도 최적화 환경을 전달한다. CI는 모드별 JSON 실행 기록을 artifact로 남긴다. 병렬 실행은 **대기시간 후보**일 뿐 처리한 suite 수나 총 CPU 계산량을 줄인다고 가정하지 않는다.

`actions/setup-python@v5`의 pip 캐시는 전역 **다운로드 캐시**를 사용한다. [공식 v5 구현](https://github.com/actions/setup-python/blob/v5/src/cache-distributions/pip-cache.ts)은 OS·아키텍처·Python 버전·의존성 파일 해시를 키에 포함한다. 실제 Torch CPU 인덱스와 직접 의존성 버전을 두 요구사항 파일에 분리해 그 해시에 넣었다. **캐시 유무와 관계없이 설치와 버전 확인은 매번 실행**한다. 현재 직접 의존성은 고정돼 있으나 pip 업그레이드와 모든 전이 의존성까지 잠근 상태는 아니며, 캐시는 과학적 재현성이나 빌드 출처 인증을 대신하지 않는다. #583에서 설치는 24초였으므로 큰 시간 절감은 suite 실행 방식에서 기대하되, 실제 효과는 변경 후 CI 로그로만 판정한다.

현재 분석은 저장된 한 열·선택된 TH16 방향과 공개 CI 로그에 한정된다. `scientific_status`와 `physical_unit_status`는 **`INCONCLUSIVE`**다.
