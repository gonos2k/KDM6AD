## Candidate A: defined retention

`INTENT(OUT)` becomes `INTENT(INOUT)` for every physical ProgB output group. The existing loop-entry zero writes then define first-call values, and later calls retain the latest value per cell until an active producer overwrites it. This is a deterministic retention contract for the shadow source, but not an inactive physical default: the result is zero when no earlier call activated the cell and a stale density/shape when a prior call did.

The contract makes reads defined but does not guarantee a valid density. At a positive trace cell that has not previously activated, `rhox` remains the seeded zero while melt/deposition/evaporation volume consumers may divide by it. If a previous call was active, the same call instead uses retained density and table parameters. A must therefore pass explicit finite/nonzero denominator assertions for every reached `qg>0` `rhox` consumer; a definedness pass alone is insufficient.

## Candidate B: per-call midpoint/zero policy

The shadow source zero-initializes all OUT arrays per ProgB cell, snapshots the entry gate once, and keeps the existing active branch unchanged. When that entry gate is inactive:

- For `qg>0`, use `rhox=rho_mid=400`, construct the corresponding shape bundle, and project `brs=qg/400`.
- For zero `qg`, leave the local parameter bundle at zero and set `brs=0`.

`S10VOL` records the action code, qg, `brs_before`, `brs_after`, `delta_brs`, and `rhox` at the selected cells and trace witness. Action 0 records the existing active density projection, 1 the positive-trace midpoint projection, and 2 zero-qg volume cleanup. The policy does not alter qg mass inside ProgB; it makes every OUT output defined and logs the brs projection as a separate physical amount.

For positive trace qg, `brs_new=qg/400` exceeds `brs_min` whenever `qg>4e-13 kg kg-1`; later ProgB calls can therefore enter the active gate because of the corrected volume state even while `qg<=qcrmin`. The gate predicate is snapshotted before the correction so its current-call branch is not recomputed from post-projection brs. Zero-qg cleanup removes a residual `brs<=brs_min` volume without changing qg mass. These state/branch differences are intentional counterfactuals and are not certified physical corrections.

The owner must still decide whether 400 kg m-3 is an appropriate model default and whether projecting the prognostic brs state is physically intended. The existing `rho_mid` declaration is a candidate hint, not approval. The zero-qg cleanup is also explicitly logged rather than hidden as a zero assignment.
