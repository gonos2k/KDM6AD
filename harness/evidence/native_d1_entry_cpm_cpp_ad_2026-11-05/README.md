# Same-call outer `entry_cpm` → D1 handoff and conditional C++ AD

This packet extends [PR #540's selected f64 D1 slope graph](../native_d1_slope_cpp_ad_2026-11-05/README.md) at native `(i,j,k)=(203,149,16)`, `runtime_call=one_step_call=2`, using the same origin checkpoint, identically prepared READY checkpoint, and one-rank/one-thread 20-second host execution. The runtime computes `entry_cpm=compute_cpm(cur.qv)` **once before its subcycle loop**; the coordinator also computes a fresh preamble cpm from its current QV, then replaces it with the outer `entry_cpm` before D1. The selected call is the **first subcycle**. This packet captures that one call; later-subcycle reuse is a source contract, not a new native observation here.

The new value-only native capture has **9,750 rows**. All **9,516 parent rows** retain their order, dtype, call identity and raw word. Six additional 39-level fields record runtime QV and the produced outer cpm, the coordinator's D1-entry QV and received cpm argument, its fresh preamble cpm before override, and its applied cpm after override. All 39 levels show raw-bit equality along `runtime QV → D1-entry QV` and `runtime entry_cpm → coordinator argument → applied preamble cpm → D1-consumed cpm`. Independent source-order scalar and Python Torch calculations reproduce the outer cpm. In this first subcycle, fresh and applied cpm are also equal at all 39 levels. The selected 16th-level values are QV `0.007321097422391176` (`3f7dfcba20000000`) and cpm `1010.6636319199112` (`408f954f1e4084cd`).

The isolated executable links the **new native static archive** and evaluates actual C++ `compute_cpm` from a separate *outer QV leaf*. It keeps a second *D1-entry QV leaf* for the fresh, overwritten preamble diagnostic. The D1 melt/state path consumes the outer cpm tensor. The earlier slope/ProgB/D1 graph and output ordering are retained; the new result appends `entry_cpm` and `fresh_cpm`. All **27 baseline C++ outputs** match the native capture or the parent C++ outputs in raw f64 bits. The joint QV direction's first 25 JVP components equal the parent packet's QV JVP exactly.

## Provenance and limits

The added runtime/coordinator capture calls strip to the exact parent source bytes. `raw/native_build_receipt.json` and paired off/on run/session receipts pin source/object/DSO/executable, native checkpoint inputs and the complete output hash. The origin-to-READY preparation is **not** raw-bit identical: its pinned comparison finds one `WE_JUST_D01_LBC` int32 element differing by 1 among 322,426,586 numeric elements. Both off/on runs start from the same READY checkpoint SHA and use the same build/input. They yield the identical **off/on full-checkpoint SHA-256**, also equal to the parent variant's output hash `225d2cabe8a466304c06ba1a04638b84c8456b8477326b6852c9217360440070`. The public replay authenticates the retained capture and checks the 9,516 parent rows as an ordered raw-bit subsequence. The new C++ build receipt pins its source, Debug/assertion build, `-ffp-contract=off`, archive, executable, Torch libraries, input and output hashes. Private executable, DSO, archive and full checkpoint bytes stay in the canonical host workspace; public CI checks the receipts and released arithmetic, not a new private build or host run.

The selected first subcycle cannot distinguish the value of outer cpm from a freshly recomputed preamble cpm because its QV values coincide. The code path and isolated AD graph show where the outer tensor is supplied, but a **native multiple-subcycle call with changed intervening QV** is required to observe the two cpm values diverge and certify later-subcycle reuse. This evidence does not establish an operational f32 or full-host C ABI JVP/VJP, physical QNICE units, a complete mass/number budget, or native-state-to-GK2A–RTTOV cost sensitivity. Both `scientific_status` and `physical_unit_status` remain `INCONCLUSIVE`.
