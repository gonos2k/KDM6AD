# Historical ice factorial source words

The four `libtorch/src` translation units in [libtorch/](libtorch/) are byte-for-byte Git source at commit `3323f015`. Their SHA-256 values equal the **then-recorded** `FACTORIAL_SOURCE_PINS` in `harness/make_ice_factorial_overlay.py`; the archive validator freezes those four original digests independently so a future generator rebase cannot alter this execution history. These are the source bytes of the 2026-10-23 ice factorial and dependent actual-QR/rain/applied-transfer historical campaigns. `libtorch/CMakeLists.txt` is from the same commit and has separately fixed SHA-256 `829b78bb0e872aadde362e3c9b65391a9d0f229fe4a459be6da798a49aae7d90`.

The `actual_qr/coordinator.cpp` snapshot is the exact output of the historical factorial and actual-QR overlay generators on these source bytes. Its SHA-256 `373e77cc9f81bd77603c6993a53cd8dfd5e9b3b401da6e102d90bc16028f280e` matches the activation observer's original source pin. `oracle/kdm6/sedimentation.py` is from commit `3323f015` and matches the historical QR-boundary receipt hash `0e2b866f1a71937fbc2cf9ff382ced8bd0e439c732992b494b2ea2251f806f89`.

The [test_sources/](test_sources/) copies are exact older test bytes selected by original source SHA in the actual-QR, applied-transfer and QR-boundary manifests. The versions are keyed by their SHA to retain both historical versions of `test_qr_boundary_evidence.py`. [The resolver](../../historical_ice_sources.py) only uses a copy when its hash equals the caller's original expected digest; any unrecognized digest remains bound to the current path and fails the historical check rather than silently receiving unrelated bytes.

This archive is for **historical replay**, not a claim that current runtime/coordinator sources still satisfy old instrumentation anchors. Current-source G3.3 overlay checks remain separate and must fail when those anchors drift. No original campaign manifest, build receipt or recorded source hash was rewritten.
