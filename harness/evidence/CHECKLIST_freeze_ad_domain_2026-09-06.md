# 동결 배분의 AD 수치 지원 범위

기준은 PR #211 병합 main `b8cd59bce31da5a50f49ec43e1d8942600908af0`다.
직전 작은 배분량·큰 합계 미분·큰 몫의 보완량 수정은 유지한다. 이번 변경은
Python `apply_freeze_controls()`가 확인된 취약 입력을 명시적으로 거부하도록
한다. 해당 입력의 미분을 복원한 것이 아니라, 지원 범위를 제한한 해소다.

## 체크리스트

| ID | 우선도 | 확인한 문제 | 해소 |
|---|---|---|---|
| F211-BUDGET-01 | P2 | 양의 subnormal 작은 과정량의 예산 VJP가 중간 반올림으로 손실 | 위쪽 정규화가 필요한 해당 입력을 보수적으로 거부 |
| F211-SOURCE-02 | P2 | 작은 합계의 raw 단위 과정량 JVP가 Inf/NaN | 내부 비율의 source tangent가 표현 범위를 넘으면 거부 |
| F211-RATIO-03 | P2 | f64 상한 근처 배분비의 reverse 중간값이 overflow | 정규화된 나눗셈의 reverse 범위를 벗어나면 거부 |
| F211-PRESERVE | 회귀 | 정상 값·미분과 None·비포화·동률·기존 극단 배분 유지 | 기존 연산식 유지 및 독립 비트 비교 |

## 수학적 근거와 제한

비음수 과정량을 `a,b`, 기준 합계를 `S=a+b`, 예산을
`B=max(reservoir,S)`라 한다. 포화 구간은 공통 제어배율을 소거하고
`c=normalize`, `D=c*S`, `G=(c*B)/D`로 계산한다. 작은 몫은
`min(a,b)*G`, 큰 몫은 `B-small`이다. 이번 수정은 이 식을 바꾸지 않는다.

유한한 전방 비율 G가 유한한 AD 중간값을 보장하지는 않는다. 현재 나눗셈의
reverse 경로는 `G/D`를, raw 단위 source tangent는 `G/S`를 형성한다.
이를 직접 계산하지 않고 `G > Fmax*D` 또는
`G > Fmax*min(S,1)`인지 검사한다. 비음수 포화 구간에서 `0 < D <= 1`이고,
`S >= 1`이면 유한한 G가 두 번째 한계를 넘을 수 없으므로 비교용 곱도 유한하다.

양의 subnormal 작은 과정량과 `c>1`의 조합은 별도로 거부한다. 예산 수반의
중간값이 subnormal에서 반올림된 후 c를 곱하면, 최종 도함수가 정상수여도
정확도를 잃을 수 있기 때문이다. 이 조건은 **보수적인 지원 제한**이며, 그
조합의 모든 개별 입력이 반드시 틀린다는 판정은 아니다. 세 조건 모두 포화
셀에만 적용하며, 하나라도 위반한 batch는 호출 전체를 `ValueError`로 거부한다.

검사는 값 전용이다. 허용되는 텐서의 미분 그래프와 배분 연산 순서는 그대로다.
alpha clipping, Inf 수반의 0 치환, custom autograd나 새 물리 정책은 없다.
이 조건을 통과했다고 모든 seed·고계 미분·유한 f64 조합을 인증하지 않는다.

## 반례와 지원 범위의 변화

| `(a,b,B,alpha)` | PR #211에서 확인한 결과 | 현재 계약 |
|---|---|---|
| `(minsub,1e-300,1,700)` | 정상 예산 미분 약 4.940656e-24 대신 VJP 약 3.308722e-24 | 거부 |
| `(minsub,1e-100,1,300)` | 작은 과정량의 예산 수반 정밀도 손실 영역 | budget 조건만으로 거부 |
| `(1e-300,1e-300,1,700)` | raw source JVP Inf, 최종 해석 미분은 ±2.5e299 | 거부 |
| `(0,1e-300,1,700)` | raw source JVP NaN | 거부 |
| `(1e-300,1.2,1.5e308,709.5)` | 전방 1.25e8, 로그 b 방향 VJP -Inf·2차 NaN | 거부 |
| `(1e-312,9e-312,1e-3,709.5)` | 전방 약 1e-4, 로그 b 방향 VJP -Inf·2차 NaN | 거부 |
| `(.001,.003,1,709.5)` | 안전한 큰 alpha의 배분 .25/.75 | 허용 |
| `(1e-320,1e8,1e9,3)` | 복원된 작은 배분량 약 1e-319 | 허용 |

이전에 VJP만 검사했던 `a=b=1e-310, B=3e-310, alpha=3` 시험도 raw source
JVP의 지원 범위를 벗어난다. 따라서 기존 수용 assertion을 명시적 거부로
바꿨다. 같은 입력의 alpha=0 비포화 값 보존은 계속 검사한다. 과거 검증 기록은
그 당시 범위로 보존하며, 이 변경을 모든 이전 입력의 미분 복원으로 부르지 않는다.

## 검증

로컬 환경은 Python 3.10.11 / PyTorch 2.13.0 / macOS CPU다. 사용자가 제공한
Python 3.13.5 / PyTorch 2.10.0 검토 및 원격 PyTorch 2.8.0 CI와 구분한다.

- 최종 전체 oracle: **1,081 passed / 26 skipped**, 48.24초.
- 집중 시험: **49 passed**. 그 안의 배분 수치 시험은 **13 passed**이며
  새 사례는 8개다. 중복된 실행 수치를 합산하지 않는다.
- 이전 b8 모듈을 메모리에서 연결하면 6개 직접 거부 사례가 모두 실패한다.
  세 guard를 각각 하나씩 제거한 별도 메모리 사본에서는 해당 조건만 필요한
  반례가 수용된다. 디스크의 생산 코드를 바꾸지 않고 시험 구분 능력을 확인했다.
- 양의 포화 입력 **256셀**에서 b8 대비 출력과 a/b/B 기울기가 모두 비트
  동일하다. 100자리 Decimal 해석 기울기에 대한 최대 상대 오차는 두 버전
  모두 약 3.76e-16 미만이다.
- 실제 Python KDM6 합성 step의 None/alpha0/.1/1/3 다섯 경우에서 출력과
  전체 상태·제어 기울기가 b8과 비트 동일하다. 실제 기상 사례 실행은 아니다.
- 부모의 경계 이웃 **40개**에서는 17개가 명시적으로 거부됐고, 허용된
  23개의 raw VJP/JVP는 유한했다. RED의 별도 12개 제한 probe에서도 추가
  미거부 오류를 발견하지 못했다. 전역 f64·고계 미분 인증으로 확대하지 않는다.
- 사용자 high-ratio 반례 두 개는 실제 b8 전체 모듈에서 유한한 값·JVP와
  -Inf VJP/NaN 2차 미분을 직접 재현한 뒤 수정본의 거부를 확인했다.
- Luna xhigh Green/Red 두 명을 재사용했다. Ruff F821/F822/F823 및
  `git diff --check` 통과. Graphify는 638파일·11,373노드·18,966간선으로 갱신했다.

원시 로그는 작업 checkout의
`graphify-out/freeze-allocation-resolution-20260906/`에 보존한다.
공개 재현 시험은 `oracle/tests/test_freeze_share_numerics.py`와
`oracle/tests/test_process_controls.py`다.

## 해석 범위

세 발견은 직접 함수의 P2 수치 경계 문제다. 실제 기상 상태에서 도달하는지와
예보 영향은 측정하지 않았다. 예산 VJP의 개별 과정량 오류가 일부 aggregate
transfer에서 상쇄되는 것은 별도 raw source JVP의 Inf/NaN을 정당화하지 않는다.
운영 f32 식, AD ABI, 창 수반 및 signed·순차 공통 보존 알고리즘은 변경하지 않았다.
M1 실제 10분 적용량 잔차, M2 최초 음수 QIB 피연산자, 입자수 단위 계약,
D4 연산 순서와 실제 예보 성능은 각각 별도 열린 과제로 유지한다.
