## Verified evidence

The four one-rank controls in [the MPI receipt](mpi_finalize_control_2026-10-08/result.json) each compiled and exited before the 20-second command deadline. The preserved logs show `MPI_Init` and `MPI_Finalize` returning `ierr=0`; observer arms log the Fortran finalize entry/return and `_Exit(0)`. The linked arms load `libkdm6_c`, `libtorch`, `libtorch_cpu`, and `libc10`. The standalone source calls no KDM6AD entry point or physics routine. `mpirun` status is its aggregate result; the separate singleton launches alone have direct-child wait status. The report does not claim an MPI-launched rank wait status or signal.

At the parent’s request, I copied the current runner and Fortran source into a new isolated directory, hashed both before/after, and repeated these bounded controls. The [pinned-witness receipt](MPI_pinned_witness_2026-10-09.json) shows stable source hashes, all four `mpirun` arms and both singleton controls returning 0, no timeout, the same configured host flags/library paths/observer, and the original external pins unchanged. Each compile and launch has a 20-second deadline. This supplies a fully pinned current-runner witness; it does not recreate the unavailable pre-edit Oct8 orchestration hash.

The [short-pair receipt](host_short_exit_2026-10-08/result.json) and saved files are internally consistent. Both 1x1, one-thread cases have harness `experiment_valid=true`, outer status 0, identical `input_sha256.json` maps, equal canonical and active-input hashes, and the same executed namelist hash. Both saved output files have the two declared times, `2025-07-19_00:00:00` and `2025-07-19_00:00:20`, and the same forecast-file SHA-256. The strict comparator was unchanged from `HEAD`; an independent rerun at frames 0 and 1 reports 254/254 exact matches, zero unsupported variables, and zero differences at each frame.

Because bitwise equality alone could pass for matching NaN payloads, I read both saved files offline with netCDF auto mask/scale disabled. Each contains 253 numeric variables and one character variable; the two selected frames contain 158,946,410 numeric values across those variables. Both files have zero NaN/Inf values. The character `Times` variable matches exactly under the comparator. This is a finite-value check for those two saved frames; it is not a physical-admissibility or conservation check for every state variable.

The host pair actually exercised the isolated private `mp337` KDM6AD conservative normalized branch. Its model log identifies `physics_variant=2`, `dry_number=1`; the copied source sets `value_only=1` before `kdm6_step_v2_c`. The WRF executable links the pinned KDM6AD dylib and its Torch libraries. This is useful evidence for that one forward-only private branch and observer behavior. It does not validate operational `mp137`, host AD derivatives, or the broader scientific acceptance criteria.

## Scientific acceptance boundary

The historical long native experiment still has `experiment_valid=false`; its exit-1 cause and a valid target-time run remain open. The 20-second pair only reaches the initial times and cannot explain the 05:55:40–05:58:00 termination. The MPI controls establish interposition/forwarding with a standalone process, not WRF shutdown. The host pair’s raw-bit equality and finiteness apply only to its two saved frames.

The separate RTTOV instrumented build measures actual extinction for one saved profile. It does not recover arrays from the historical executable, cover all eight retained profiles, separate individual gas species, or validate JVP/VJP, independent directional differences, or applied process budgets. Cloud QA, pixel UTC, parallax datum, common footprint, and the clear-sky versus retrieved-liquid mismatch remain open. Forecast skill and unattended cycling remain separate objectives, not completion gates for this validation.
