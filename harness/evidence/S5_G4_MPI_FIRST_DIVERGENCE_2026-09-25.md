# S5 G4 MPI first-divergence status — 2026-09-25

**Status: OPEN. No cause is assigned to the observed 2×1 divergence.** The earlier accepted C2 trace remains useful for localization. A later halo follow-up executable was built with the wrong WRF source-generation path and fails its 2×1 output gate, so its captures are retained only as a rejected setup/build experiment.

## Accepted earlier localization

The G4 normalized-mp237 serial and 2×1 archived histories differ at t=20 s. The shadow relink against the retained G4 module and current host archive passed the archived-history gate for both decompositions: 254 common history variables matched at t=0 and t=20. Here **254 means 253 numeric variables plus the byte-exact character variable `Times`**.

The accepted S5 C2 probe first found owner-cell `ww` differences after `rk_step_prep`, at i=117 (the 2×1 seam) and i=234 (the eastern band). The stage-0/1 `calc_ww_cp` caller snapshot compared 5,916,720 binary32 words across its declared i windows with no mismatches. That snapshot held owned columns only; it did not prove the complete stencil inputs or neighboring halo copies were equal. A separate KDM-entry snapshot already differed, with the first reported value a one-ULP `TH` difference at `(i=110,k=39,j=83)`. The producer localization is therefore strong, but the exact first operand divergence remained open.

The private host `calc_ww_cp` source was inspected at SHA-256 `27ce690b27b24c80247a5551b48d37fc32fc47470d806cbef1bb859d58edc31c`. It computes `muu`/`muv` from `mup`/`mub`, then `divv` from `u`, `v`, map factors, `c1h`, `c2h`, `dnw`, `rdx`, and `rdy`. The selected outputs at i=117 and i=234 require, respectively, the eastern i neighbor and the south/north j neighbors. The earlier owner-only snapshot was insufficient to exclude those values.

A bounded, lossless projection of the accepted C2 trace is now public at [S5_G4_C2_selected_trace_2026-09-25.npz](data/S5_G4_C2_selected_trace_2026-09-25.npz), with raw source-dump hashes and provenance in its [manifest](data/S5_G4_C2_selected_trace_2026-09-25.json). It contains all declared G33 groups/fields for owned columns i=117 and i=234 at each declared stage, plus the selected KDM-entry `TH` words. The [replayer](../s5_g4_selected_trace.py) recomputes the first difference in this **published selected projection** as stage 2/group 2/`ww`/i=117 (9,890 words); i=234 adds 9,970 `ww` differences at that stage. The selected KDM value at Fortran `(i=110,k=39,j=83)` is `1139747349` vs `1139747350` in raw uint32 words. This artifact does not reopen the full private G33 or KDM dump and does not prove the full-domain first-difference claim on its own; the original dump sizes and SHA-256 values remain in the manifest.

## Rejected halo build and control

The first expanded group-5 probe was compiled directly from uppercase `solve_em.F`. Its serial 1×1 history matched archived G4 (254 common = 253 numeric + `Times`), but its 2×1 history did not: 225/254 common variables matched and 29 differed. Running the **same executable** with the dump environment variables unset reproduced the same 29-variable difference. This shows the dump environment alone did not explain that build’s result; it does not identify a physical or code-generation cause.

The direct-`.F` build is a material confound. On the same earlier S5 owner probe source, direct `.F` compilation produced object SHA-256 `1876f55b3aa8c6d587110627af82fcf0060fa71241c1e9528f81f2873982dd68`. Replaying the WRF preprocessing pipeline—comment cleanup, WRF macro `cpp`, `tools/standard.exe`, final `cpp`, then the recorded `mpif90` command on `.f90`—reproduced the prior accepted C2 object byte-for-byte at SHA-256 `e44592a150c0b85320fb49c0c50f1e43837a105037e76b3ff4d912e26ea7a8e6`. The failed direct-build captures must not be used to attribute the G4 MPI divergence.

## Exact-build stencil follow-up

The accepted C2 public projection and the rejected direct-`.F` halo experiment remain distinct. The corrected executable followed the retained WRF source-generation path: comment cleanup, WRF macro `cpp`, `tools/standard.exe`, final `cpp`, then the exact recorded `mpif90` command on `.f90`. The overlay was generated from pinned `solve_em.F` SHA `d66e9db1bba8f37e3f46d30c2fd74bdf8def411adf233376a69e0b401c6d3d1f`; its guard-stripped source matches byte-for-byte. The final group-5 overlay SHA is `bf07ce040bf6b60c5806ac39112d17e13074f73146054a2d89fe1b016069508e`, preprocessed `.f90` SHA `a0085cc20d2d29e8f96b38a8894653178d907138f6cf4bd1ee9b75759e688c4c`, object SHA `7ba833c4a0dca10e6c60d4355d08fe710047695eaedb3914027aee1f4ba21b44`, and isolated executable SHA `e3f5d13309a5bbebc54db64e1445f8675303e800b7e36d2077c45c4be8c43f48`.

Both exact-build dump-off controls matched their archived G4 t=20 frames bit-for-bit, and each same-executable dump-on capture matched its dump-off control. Each comparison had 254 common variables: 253 numeric variables and exact `Times`. The 1×1 and 2×1 run identities have the same canonical input and namelist-without-grid hashes; the requested/actual processor grids are recorded. The bounded public trace is [S5_G4_exact2_halo_stencil_trace_2026-09-25.npz](data/S5_G4_exact2_halo_stencil_trace_2026-09-25.npz), with its provenance/raw hashes in the [manifest](data/S5_G4_exact2_halo_stencil_trace_2026-09-25.json) and executable replayer in [s5_g4_halo_trace.py](../s5_g4_halo_trace.py).

At RK entry, the group-5 snapshot includes every `calc_ww_cp` caller field over the selected stencil neighborhoods i=116–118 and i=233–235 and j=0–283. The projection compares **297,924** binary32 words across serial and 2×1 with no mismatches. Within x2, the seam halo/owner values at i=117 and i=118 match across **99,308** words. The east-staggered non-owned value i=235 also matches between layouts. Across the selected output probes, the earliest remaining difference is stage 2/group 2/`ww`: 9,890 words at i=117 and 9,970 at i=234; the maximum absolute differences are (4.14252\times10^{-6}) and (4.29153\times10^{-6}), respectively. The public replayer recomputes these selected-window results and verifies the NPZ digest; it does not reopen the private full-domain dumps.

The call bounds still differ by decomposition. `solve_em.F` passes each tile’s `i_start/i_end` to `rk_step_prep`; `module_em.F` then passes those `its/ite` values unchanged to `calc_ww_cp`. The metadata records 1×1 tiles with i=1–235 and 2×1 rank tiles i=1–117 and i=118–235; the j tiles are 1–142 and 143–283 in both layouts. `calc_ww_cp` sizes local work arrays from `its:ite`, so equal selected caller arrays do not by themselves separate code generation from call-bound/loop-extent effects. The current evidence excludes a stale or different selected stencil input as the explanation at i=117/234; it does **not** prove an arithmetic/compiler cause.

The stage snapshot is taken at the RK entry before `rk_step_prep`. Source inspection of the intervening calls shows `calc_mu_uv` reads `mu/mub` and writes `muu/muv`, while `couple_momentum` reads `u/v` and writes `ru/rv/rw`; their relevant inputs are `INTENT(IN)`. `module_em.F` then passes those unchanged arrays and the same `its/ite/jts/jte` arguments to `calc_ww_cp`. This source path supports treating the captured group-5 values as the callee’s input values at the selected call. The private source hashes are listed in the trace manifest; no source text is copied into the public artifact.

S5 therefore remains **OPEN**. The next causal experiment should vary one factor at a time on the exact same input/object pipeline: first the `calc_ww_cp` vectorization/contraction option, then call-loop bounds if necessary. Preserve the original G4 failure and do not change operational defaults. The full-domain MPI failure and other first-divergence locations remain broader than the selected trace projection.

### Bounded counterfactual plan (not executed)

The one-factor plan keeps the corrected WRF preprocessing path, the exact normalized mp237 input, and the current exact2 G4 objects as the baseline. The pinned dynamics source is `module_big_step_utilities_em.F` SHA-256 `27ce690b27b24c80247a5551b48d37fc32fc47470d806cbef1bb859d58edc31c`; its normal object flags are `-O2 -ftree-vectorize -funroll-loops` plus the recorded host compatibility/I/O flags. All arms use the WRF `sed → macro cpp → tools/standard.exe → cpp → mpif90 .f90` pipeline and replace only `module_big_step_utilities_em.o` in an isolated copy of the shadow archive. Direct compilation from uppercase `.F` remains rejected.

First, a small driver around the pinned `calc_ww_cp` uses the same published selected caller words (i=116–118 and i=233–235, j=0–283, vertical vectors, and scalars) and changes **only** `its:ite`: serial 1–235; x2 rank 0 1–117 for i=117; x2 rank 1 118–235 for i=234. Keep the j tile bounds fixed at 1–142 and 143–283 and the compiled object unchanged. This tests whether the call extents alone reproduce the selected outputs; it remains a local routine experiment, not a full host replay.

If bounds alone are insufficient, build separate shadow-host counterfactuals: arm V appends only `-fno-tree-vectorize` to the one-object compile; arm C appends only `-ffp-contract=off`. Do not combine flags. For each arm, retain all other objects and inputs, run the same 20 s fixed-dt 1×1/2×1 cases, and compare each dump-on capture with its same-executable dump-off control. A compiler-option effect is supported only if the relevant group-5 caller words remain unchanged and the selected stage-2 `ww` discrepancy changes. No counterfactual has been run; the S14 native lane has priority.
