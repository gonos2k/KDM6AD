# Native number units and applied-change interpretation

The local first-order KDM→RTTOV composition accepted in PR #431 remains
complete within its declared scope. This audit addresses its two remaining
interpretation questions without rerunning the model, KDM or RTTOV:

1. The NC/NI host carrier and KDM equations have a source-supported **unit
   boundary conflict**. There is no current single consistent host/kernel/
   optical number convention to certify.
2. Saved arrays separate KDM state change, host cleanup and total applied
   change. Small QI removal is not a KDM process rate, a number transfer or a
   closed water/energy budget.

## NC/NI source-to-consumer contract

The [unit contract](../../../docs/NATIVE_NUMBER_UNIT_CONTRACT.md) gives the
producer/import, Registry, dry-mass scalar-RK, mp37/mp137 wrapper, internal KDM
and optical consumer table, exact source anchors and hashes.

Host Registry declares `QNCLOUD`/`QNICE` in `# kg-1`; the conservative scalar
RK measure is dry-column mass. Inputs are interpolated into those scalar
slots without a density conversion. Both wrappers pass NC/NI numerically
unchanged. In contrast, KDM's DSD relation

\[
\lambda^{d_m}=\frac{C N}{\rho_d q},\qquad
N=\frac{\rho_d q\lambda^{d_m}}{C}
\]

with the species mass coefficient/exponent requires volume number `# m-3`
when the water mixing ratio is per kg dry air
and `DEN=1/(AL+ALB)` is dry density. The corresponding public C++/Python
formulas agree. Limiter-generated number values are also returned unchanged
to the per-dry-mass scalar carrier. Matching mp37/mp137 values cannot resolve
a conflict shared by both boundaries.

The physical basis of every historical external input/restart payload is
not established by metadata alone. A raw value retained from an earlier KDM
call may already have volume semantics; multiplying it by density again would
not repair that history. The previously used optical bridge's `rho_d*NC/NI`
mapping remains a conditional Registry-basis mathematical interpretation.
Its verified derivatives are not retroactive proof of physical unit closure.

Native `DEN` in the selected `moist_physics_prep_em` path is already dry;
the saved replay checks that identity at all 39 layers. The generic public
`dry_number` option computes `forcing.rho/(1+QV)`. It must not simply be
enabled with native DEN. Supplying synthetic moist density to make that
expression return dry density changes the separate physical `den` operand,
so that alone is not a coherent native fix either. A future versioned
boundary needs explicit dry-density number conversion at entry, its inverse
at exit, matching initialization and checkpoint provenance/migration, while
preserving the native physical forcing coordinate. The contract provides
the live-density JVP/VJP terms, including accumulation across species.

**This audit changes no physics, ABI, optical defaults, saved model state or
operational executable.** It identifies the conversion boundary rather than
silently reinterpreting legacy inputs.

## Applied water-change ledger

`applied_change_ledger.json` is generated by
`python -m harness.audit_applied_budget` from the unchanged #431
`native39_composed_cost.json` (SHA-256
`465aed12f8d8fa42f50b5ffd5b4aa8a24023f05fbdc0b3e137054e6098481bf8`).
The input is the selected continuous-fp64 local map at native `(156,21)`,
39 layers, trace step 2, reconstruction checkpoint `00:00:40`, `dt=20 s`.
The earlier raw-bit host replay and this fp64 state-change arithmetic remain
different evidence; the current audit makes no new f32 forward-parity claim.

For each water species it stores per-layer differences and mean rates:

\[
\Delta q_K=q_{\rm raw}-q_{\rm before},\quad
\Delta q_Z=q_{\rm clean}-q_{\rm raw},\quad
\Delta q_{\rm applied}=q_{\rm clean}-q_{\rm before}.
\]

The column diagnostic uses the same fixed captured MP-entry
`w_k=DEN_k*DELZ_k`, multiplying after promotion of the REAL4 operands to
binary64. Units are `kg dry air m-2`; multiplying by declared water mixing
ratios gives `kg water m-2`. This is an explicitly chosen density-thickness
layer measure. It is **not** a dry-mass RK flux ledger or a claim that its
column sum is exactly `MU/g`. No cell-area/map-factor integral is inferred.

| Term, six water species | Change under fixed `DEN*DELZ`, kg m⁻² |
| --- | ---: |
| KDM raw state minus input | -0.0012985493228218482 |
| Cleanup minus raw state | -0.0000005449928770924286 |
| Applied clean state minus input | -0.0012990943156989405 |
| Algebraic split residual | 7.03e-25 |

The very small final row verifies the decomposition identity, **not physical
conservation**. The state+forcing ABI result stored for this fp64 call does not
contain matching rain/snow/graupel surface exports or process-transfer ledgers.
Therefore the raw KDM change cannot be closed against sedimentation or
attributed to a specific physical process from these arrays alone. Reusing
surface precipitation from a different f32 call would mix executed paths.

The density-thickness weights sum to `9739.965539781619 kg m-2`.
With the saved `MU=95492.28125` and source-audited binary32 gravity
`9.8100004196167`, `MU/g=9734.17708107816 kg m-2`; the difference is
`5.78845870346 kg m-2` (about `0.05947%`). This explicitly prevents treating
the chosen diagnostic quadrature as the exact mass-coordinate measure.

### Cleanup and retained number

Only QI changes between kernel and cleanup: levels **19, 20 and 21** remove
`2.0014e-11`, `1.6398e-10`, and `1.19780629213e-9 kg/kg dry air`, respectively.
They are below the independently audited executed-namelist binary32 threshold
`9.99999993922529e-9`. The old public source report does not store that
threshold as a scalar. The companion manifest binds the executed namelist's
hash and threshold audit; this ledger reads the recorded before/after arrays
and does not independently recompute the cleanup rule. The total
fixed-measure removal is `5.44992877092e-7 kg m-2`. QV receives no cleanup
correction in this case. The generic ledger separately records additions
when a negative raw value is clamped, so it does not assume all cleanup is a
sink.

At those three newly zero-QI levels, raw NI remains approximately
`90.5354`, `439.1127`, and `1881.8218`, unchanged by cleanup. Under
`MP_ZERO_OUT=2`, `MP_ZERO_OUT_ALL=0`, the cleanup acts on `moist`, not the
number `scalar` fields. These are inactive mass entries with retained raw
number; no compensating number transfer is inferred. NN/NC/NI/NR all remain
exactly identical across cleanup. Their kernel differences are recorded as
**raw operands**, with no dry-number inventory or number conservation claim.

The saved QV/QC applied rates agree exactly with the cleaned-minus-input
differences divided by dt. `THM_after - (THM_before + dt*H_RATE)` has maximum
absolute residual `2.84e-14 K`, consistent with fp64 expression grouping.
Heating is an applied moist-theta rate, not a complete energy budget in J/kg.
No new vapor or latent-heat compensation is introduced for cleanup removal.

## Validation and limits

Twelve focused NumPy-only tests cover an independent two-cell inventory,
cleanup removal and negative repair, number/mass pairing, exact applied-rate
checks, unsupported physics/basis flags, nonfinite/invalid measures and
output-alias refusal. The diagnostic reads immutable input and performs no
AD, optimization, native integration or RTTOV call. The receipt/manifest binds
the prior report, new helper/tests, unit contract and private source hashes;
the private host sources themselves are not published.

The +40 s nominal observation offset, unknown pixel time, fixed surface/viewing
conditions, source-reconstructed P8W, unresolved whole-reference pressure
discrepancy and absent full-host/RK/retained-memory adjoint from #431 remain.
This source/array audit neither reruns nor revises that accepted local
derivative result. It resolves the location and nature of the unit conflict
and records applied-change components; a coherent number-basis repair and
closed physical budgets remain separate future work.
