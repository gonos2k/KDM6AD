## Conditional thermal chain

The executed entry computes `cpm=cpd*(1-max(QV,qmin))+max(QV,qmin)*cpv`; the cpm computed before subcycling is the one applied at D1. `work2` is produced from pressure, physical temperature and density, without QV as a direct operand. On the selected active, uncapped D1 branch, snow melt supplies the signed applied amount `A_s`, then `t1=T+(xlf/cpm)*A_s`. Graupel raw melt reads **that** `t1`, together with `work2` and the already traced `precg2`/slope operands. Source-order value replay and JVP checks retain both the snow-amount and cpm terms in `D(t1)`; QV's selected direct `work2` tangent is checked as zero rather than inferred from a small difference.

The independent Python `work2` formula uses a **16-ULP local diagnostic bound** against the stored C++ word. This bound does not certify portability of the entire replay: the inherited D1 melt source-order reconstruction still requires its derived intermediates to match raw bits, and the ten available native TH/QV endpoints separately require raw equality of the consumed `work2` word. Other libm-sensitive paths and uncaptured endpoints are not granted a whole-call tolerance by this diagnostic.

## Limits

This is one native column and a selected f64 full-call branch. A D1 input's total TH/QV tangent can include earlier state evolution; source-order decomposition of the local D1 formula is not an independent process-off experiment. A smooth D1 branch does not imply that downstream activation, limiter or NCCN branches are smooth.
