# PR395 intake and analysis consumer audit

**Result:** the selected-column data path and one-step `H(M(xb))` slot semantics are source-consistent. The consumer now binds producer identity to the archived effective namelist, rejects masked selected inputs before `np.asarray`, and rolls back both outputs after the injected post-link failure. No live forecast, native M step, H, or RTTOV was read or executed in this audit.

The audit ran in `/private/tmp/KDM6AD-pr391-saturation-controls-20261009` on branch `codex/pr396-team-audit`, HEAD `e74cf3fabd`; the merged code base is `f447477d`. A targeted Graphify query found `run_ss_case`, `selected_frame`, `State`/`Forcing`, and capture-helper dependencies; I followed each path through the source. All file-backed run and NetCDF inputs below live under `graphify-out/pr396-audit-green/` and are marked synthetic.

The intake’s literal `current_worktree_head=8e5aab06…` is the checkout recorded at native launch in `LIVE_START.json`, not the worktree at later extraction/audit time (`f447477d` after PR merge; `e74cf3fa` during this review). The run’s compiled source snapshot is separately recorded as `30931e52…`, and `current_head_build_claimed=false`. Treat that field as the launch checkout head; its name alone should not be read as an extraction-time head or build attestation.

The new intake now reads `ncmin_land`/`ncmin_sea` from the archived effective `run_dir/namelist.input`. `run_ss_case.py` copies the effective namelist into the run archive before it restores the case copy. The synthetic fixture deliberately set archived values to 5/6 and restored case values to 10/10: intake rejected the archive. It then accepted the corrected archived 10/10 file, so the receipt identifies the run’s executed settings.

The analysis driver no longer hashes its module-level default intake paths inside `build_run_inputs`. `main()` supplies the manifest and NPZ hashes it actually validated, including CLI overrides. The synthetic flow passed those custom paths through both analysis preflight and `_validate_intake_binding` in the capture helper.

Both intake writers now roll back their exclusive hard link if removing the temporary link fails after publication. One injected `Path.unlink` error at that exact point left no manifest, NPZ, or temporary file. The check covered the cross-file failure path: a failed manifest publication also removed the NPZ already linked by the intake.

The root requested a narrow gate for the effective run configuration. The intake now binds the `run_identity` scheme, label, runtime length, output intervals, rank count, actual `1x1` grid, and path-independent effective-namelist hash to the archived `namelist.input`; it also requires `mp_physics=337`, 20 s `time_step`, and both adaptive-step flags `.false.`. It deliberately does not require `run_identity.controls.fixed_dt=true`: the real launch omitted that CLI flag, while the archived effective namelist records fixed-step values. A producer-shaped synthetic identity with `fixed_dt=false` and those effective values passes; the same identity with archived adaptive stepping enabled fails before forecast extraction. This matches the run producer’s distinction between an invocation flag and the effective settings the model used.

The live forecast’s `Times` still must equal all eight exact labels. The `State` and one-entry `Forcing` come from frame index 0 (`2025-07-19_05:55:40`); the analysis advances that background once using the fixed 20 s forcing and sets `obs_time=1`, so `Jo0` is `H(M(xb))` at the nominal `05:56:00` slot. The second saved frame is timestamp context; the driver does not substitute its native state for the analysis slot and does not run a direct H on the 05:55:40 state. The observation receipt and run manifest keep pixel time unverified and science/matchup acceptance false. WRF `Times` are model time labels; the AMI pixel’s UTC remains unproven.

The field reconstruction follows the archived reader and WRF Registry. At `USE_THETA_M=1`, `THM+300 K` is moist potential temperature; the KDM6 `State.th` is its dry-potential form, `(THM+300)/(1+(Rv/Rd)QVAPOR)`, and physical temperature is `th*pii`. `QVAPOR` and the water species are stored as `kg kg-1`; pressure centers use float64-first `P+PB`, while EOS density uses the moist-potential-temperature form. The intake retains raw `PH` and `PHB` separately. Its native P8W is a Python REAL(4) transcription of the archived `calc_p8w` source, not an executed host P8W output. The RTTOV grid preserves the 39 native centers and 40 native interfaces and adds the fixed 27-layer upper reference profile; it does not remap model levels.

The intake now also retains `selected_frame.host_dry_mass_kg_m2` as float32 for all eight frames (`native_window_host_dry_mass_kg_m2`, shape `[8,39]`) and the background vector (`host_dry_mass_background_kg_m2`, shape `[39]`). This is the host eta-layer dry mass from `-(C1H*(MU+MUB)+C2H)*DNW/9.81`, with `C1H`, `C2H`, `DNW`, `MU`, and `MUB` consumed in the archived reader's REAL(4) path. It is separate from EOS `rho_m*delz`; no mass-budget claim follows from either column measure alone.

The driver now preserves the callback's raw `grad=False` all-zero-mask cost as `background_quality_probe_callback.raw_zero_mask_J_huber` / `objective_audit.background_quality_probe.probe_masked_cost`. It records optimizer `Jo0_huber` from `objective.initial_zero_control_closure.Jo` separately. A pure synthetic receipt test recomputed the saved probe BT using both its all-zero mask and the first closure's frozen seven-channel mask: the former cost was 0, the latter equaled the first closure `Jo0` (0.875 in the synthetic fixture). It also verified the probe and first `grad=True` H receipt shared BT and state hashes. This calculation calls no H or M.

Number and volume units remain bounded by their declared sources. The Registry labels `QNCCN`, `QNCLOUD`, `QNICE`, and `QNRAIN` as `# kg-1` without stating a dry-versus-moist mass basis; `QIB` is `m3 kg-1`. The host wrapper separately describes its first-call CCN seed as volume concentration and divides by dry density before the normalized-dry ABI call. The intake copies saved QN fields and `QIB` verbatim and does not certify a physical number-unit calibration. Keep that limitation visible in downstream budgets and analyses.

The analysis template path is the retained old paired RTTOV case. Source inspection shows it is copied into a fresh private workspace; old direct/K output trees are cleared, old cloud content/fraction are zeroed, pressure/interfaces and T/Q/O3/CO2 are rewritten from the new intake, and the current State generates cloud inputs for every H call. Geometry is built from the fixed AMI GEOS candidate and native HGT; dynamic skin and near-surface fields come from the new native column. The retained fixture contributes the coefficient/test-driver template and static sea-surface parameters. A synthetic missing-template path failed closed. No old forecast, checkpoint, or BT target is an input to the analysis driver.

Selected NetCDF values need mask checks before `np.asarray`: the archived helper itself uses `np.asarray` on state slices, and a finite `_FillValue` then loses its mask. In the synthetic fixture, a masked selected `QNCCN` became finite `9.969e36` in the archived reader. The new intake now rejects that selected slice before the reader converts it. The valid-column boundary case also passed: a fill mask at a different grid cell did not require a whole-field read or block the selected `(86,48)` intake. This is conditional evidence from a synthetic file; it does not establish that the live native column contains a mask.

The extractor intentionally does not stream-hash the multi-gigabyte forecast. It records exact selected-array hashes plus forecast size/mtime before and after reading; `forecast_sha256` is explicitly null. `run_ss_case` creates a unique archive, removes old case outputs before launch, and copies the produced forecast into that archive. The retained receipt therefore attributes the consumed selected arrays and run metadata, but it does not provide a whole-file content digest against later replacement that preserves size and mtime.

Validation was limited to `py_compile`, Ruff E9/F63, custom manifest/NPZ path binding, the synthetic file-backed intake/receipt flow (including host eta-mass key/shape/type/provenance checks), fixed-versus-adaptive effective-namelist cases, a selected-mask versus unselected-mask boundary, one post-link publication fault injection, the zero-mask-versus-`Jo0` synthetic receipt regression, and `git diff --check`. No live native input was opened and no model/H/RTTOV operation ran.
