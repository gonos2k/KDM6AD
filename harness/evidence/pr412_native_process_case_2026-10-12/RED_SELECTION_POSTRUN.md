The original bounded native read completed its private slice and guards, then exited at public JSON serialization with `TypeError: Object of type int64 is not JSON serializable`. `SELECTION_FAILURE.json` records exit 1, stage, plan/selector hashes, and the preserved slice hash; `SELECTION_RESULT_EMPTY_AFTER_FAILURE.empty` remains present and the original `SELECTION_RESULT.json` was never published. The cause is visible in the frozen selector: `j` and `i` come from NumPy `argwhere` and enter the selected-result mapping as NumPy integer scalars. The recovered result does not disguise that original failure or claim the selector itself returned exit 0.

The separate recovery source binds the unchanged original plan, selector, failure receipt, and private NPZ hashes. It reads the NPZ and rechecks the small WRF `Times` metadata for receipt completion; source inspection shows it does not reread any native state arrays or widen the selection. Its recovered result is therefore a postprocessor result over the one preserved slice, not a second native scan. A new execution of the unchanged original selector with a nonempty candidate would still encounter the JSON integer serialization bug; the frozen executed source should remain unchanged, and any future selector fix would need a new version and a separately authorized scan.

I independently read only the saved private NPZ, recomputed the finite/nonnegative/pressure/geopotential/companion-proxy screens, warm-cloud criterion, frozen-mass threshold, eligible mask, and Haversine distances from the stored 41×41 arrays, and compared every saved array inventory hash. The recomputed masks match the NPZ masks; all 1,681 cells pass the finite screen and open-ocean test, 41 satisfy the warm-cloud criterion, all 1,681 meet the frozen-mass threshold, and 41 are eligible. Sorted by distance then `(j,i)`, the first three candidates are `(103,48)` at `86,798.621 m`, `(103,49)` at `86,948.941 m`, and `(103,47)` at `86,948.999 m`. The recovered selection `(j=103,i=48)` matches the nearest candidate exactly. Its saved values are QC max `3.46020e-5 kg/kg dry`, one warm threshold layer, and `T=294.88985 K` on that layer.

This identifies a native model state with a warm liquid-cloud mass threshold and frozen hydrometeor masses below the declared threshold. It does not demonstrate that a KDM process fired, quantify a process rate or response, establish observed cloud phase, or claim science acceptance. It is `86.799 km` from the original native center. The original center AMI pixel cannot be reused as its observation. Any later V4 work must bind the geographically nearest actual pixel from the same nine Jul19 AMI files to this selected column before residual inspection, keep the 2.5 km and seven-channel DQF gates, and stop if those gates fail; do not try another native candidate. No BT values or residuals were read for this selection.

The recovered record states no region expansion, one native-array scan, and zero native integrations or M/H/optimizer calls. Its forecast provenance remains bounded: the full forecast was not rehashed; path, source run receipts, saved time metadata, and size/mtime stability are recorded. The failure receipt itself is the preserved exit-1 record; no separate stdout/stderr execution log or coordinator exit marker is present in this packet, so that exit attribution is not independently attested beyond that receipt.
