## 이론과 구현

비음수 D2/D3 과정량을 a, b, 기준 합계를 S=a+b, 예산을
B=max(reservoir,S), 공통 배율을 s=exp(alpha)라 한다. 포화 구간에서는
`s*a * B/(s*S) = a*B/S`이므로 공통 배율을 소거한다. 비포화 구간과
정확한 draw=budget 동률은 기존 scaled 값을 직접 반환한다.

`(a/S)*B`는 최종 값이 표현 가능해도 a/S가 먼저 0이 될 수 있다.
`a*(B/S)`만으로 바꾸면 일부 1차 미분은 복원되지만 큰 S의 2차 미분은
여전히 소실된다. B와 S를 동일한 2의 거듭제곱 c로 정규화하여
`a*((c*B)/(c*S))`를 계산한다. B>=S이고 포화된 scaled 합계가 유한하므로
B/S는 유한한 공통 배율로 제한된다. 정수 지수 선택은 값 전용이며 B와 S의
미분 그래프는 유지한다. c의 상한은 f64의 `1/tiny`로 두어 subnormal S에서도
정규화 배율이 overflow하지 않게 한다. 비활성 분기는 계산 전에 피연산자를
1 또는 0으로 격리한다. epsilon 예산이나 alpha clamp를 추가하지 않는다.

부모 재검토에서 큰 배분량의 자기 미분도 직접 비율식에서는 상쇄되는 것을
확인했다. 두 과정량 중 작은 것을 위 식으로 계산하고 큰 것은 B-small로
계산한다. 비음수 두 과정량이라는 동결 계약에서 같은 실수 산술 배분이다.
동률의 값 전용 선택도 동일한 해석 미분을 준다. 이 수치 계산을 signed·순차
공통 보존 제한기의 물리 예산과 합치지 않았다.

## 직접 반례와 독립 기대값

| 입력/검증량 | main 13be1b25 | 수정본 |
|---|---:|---:|
| a=1e-300, b=1e300, B=1e301, alpha=3의 작은 배분량 | 0 | 약 1e-299 |
| a=1e-320, b=1e8, B=1e9, alpha=3의 작은 배분량 | 0 | 약 1e-319 |
| a=1, b=1e200, B=1.5e200, alpha=.5의 작은 배분량 raw dY/db | 0 | -1.5e-200 |
| b=1e200 exp(beta)의 작은 배분량 beta VJP/JVP/2차 미분 | 0 / -1.5 / NaN | -1.5 / -1.5 / +1.5 |
| 같은 입력의 큰 배분량 raw dY/db | 0 | +1.5e-200 |
| 큰 배분량 beta VJP/JVP/2차 미분 | 미분 상쇄 | +1.5 / +1.5 / -1.5 |

작은 값의 기대값은 실제 f64 입력을 Decimal로 옮겨 독립 계산했다.
작은 출력의 중앙 beta 차분은 -1.5000000000209288이다. 큰 출력은 약
1.5e200이어서 이 섭동의 출력 변화가 f64 간격보다 작다. 큰 출력의 직접
차분은 0이며 이를 미분 검증 성공으로 세지 않는다. 해당 수반은 독립 해석식과
해상 가능한 작은 보완량의 미분으로 확인했다. 기대 미분이 1e-200인 시험은
절대 허용오차를 0으로 설정하여 잘못된 0 수반이 통과하지 않도록 했다.

## 실행 검증

로컬 환경은 Python 3.10.11 / PyTorch 2.13.0 / macOS CPU다. 사용자가 제공한
Python 3.13.5 / PyTorch 2.10.0 독립 검토 환경과 구분한다.

- 전체 로컬 oracle: **1,073 passed / 26 skipped**, 60.83초. 외부 자산 skip은
  실제 위성·RTTOV 실행 성공으로 계산하지 않는다.
- 최종 집중 시험: **41 passed** (`test_process_controls.py`,
  `test_audit_runtime_boundaries.py`, `test_freeze_share_numerics.py`).
- 새 portable 시험은 **5개**다. 이전 main 함수를 메모리에서 적용하면 5개가
  실패한다. 정규화만 하고 큰 배분량을 직접 계산하면 1개, 정규화를 제거하면
  2개가 실패한다. 단순 괄호 이동과 불완전 후보를 구분하는 회귀시험이다.
- Luna xhigh Green/Red 두 명의 최종 재검토에서 추가 P1/P2를 확인하지 못했다.
  각 팀의 32 passed는 위 집중 시험과 중복되며 합산하지 않는다.
- 일반 scalar 24개 비교에서는 출력 비트가 같다. 별도 양의 포화 256셀에서는
  main과 최대 2 ULP 차이가 있고, 100자리 Decimal 해석 기울기에 대한 최대
  상대 오차는 수정본 3.76e-16 미만, 이전식 약 1.47e-3이다. 아주 작은
  도함수의 상쇄 때문에 이전식과의 상대 차이가 클 수 있다.
- Red의 독립 포화 10,000셀 스윕은 이전 직접 비율식과 최대 3 ULP 차이를
  기록했다. 두 출력의 합에는 최종 덧셈 반올림이 남으므로 모든 셀의 합이
  예산과 raw-bit 동일하다고 주장하지 않는다. 제어된 f64 포화 출력 전체의
  과거 비트 보존도 보장하지 않는다.

## 해석 범위와 열린 과제

이 변경은 표현 가능한 결과를 불필요한 중간 연산에서 잃던 직접 함수 경계를
고친 것이다. 정확한 raw 수반 자체가 f64 최소 subnormal보다 작으면 저장할 수
없다는 한계는 여전히 존재한다. 모든 유한 입력·고계 미분의 전역 인증은 아니다.
운영 f32 식, C/Fortran AD ABI, 창 수반과 일반 signed 보존 알고리즘은 변경하지
않았다. 실제 WRF/MPI 예보·live RTTOV 동화는 실행하지 않았다. M1 실제 10분
적용량 잔차, M2 최초 음수 QIB 피연산자, 입자수 단위 계약, D4 연산 순서 및
실제 예보 성능은 각각 별도 열린 과제로 유지한다.
