# Native selected-column execution successor — blocked draft

This packet is a **source-only successor draft** for the same native `(203,149)` column and #588's 45 full 624-word f64 inputs. `draft.json.gz` keeps the parent plan SHA, #591 policy commit, 100 ordered call slots, 900-second ceiling, Legacy controls and 21 represented JVP directions. It carries 28 measurement **group IDs** and 19 proposed mask IDs. `atomic_catalog_draft.json` expands those groups to **191 source-site, operand and blocker entries**, all still `BLOCKED` or `UNRESOLVED`. Source-site order is not demonstrated runtime execution order, and the entries are not emitted capture fields.

The draft deliberately has `status=DRAFT_BLOCKED`, `execution_receipt=null` and null source-diff, atomic-field-catalog, compiler, DSO, dependency, loader and watchdog hashes. `require_execution_ready()` always rejects. The unit-neutral `same_call_total_precipitation_raw` sidecar in synthetic tests is a raw numeric coordinate; the `FnResult` rain unit and measure have not been approved.

`successor.py` validates only synthetic structure: planned call/input words, value outputs and a same-call rain sidecar, 21 represented-direction seed arrays and JVP words, one named VJP cotangent, group/mask identifiers and layer/column event identity. A matching synthetic bundle **cannot** establish that any proposed tensor was captured, that its physical expression is correct, or that an installed DSO was built and loaded. The result remains DRAFT_BLOCKED and never authorizes execution.

`validate_atomic_catalog.py` separately checks the 191 entries and 19 masks against a SHA-pinned archive of ten public `libtorch` source files. It verifies exact cited source lines, group membership and explicit blocker labels. Inline minimum operands and realized per-species departure/arrival/export remain unresolved; neither a lexical line reference nor a candidate flux certifies the applied graph node or physical budget. The successor draft pins this catalog SHA as a **draft dependency**, while its independently reviewed executable atomic-field pin stays null.

Validation is tied to the complete, SHA-pinned catalog bytes. A caller cannot replace a consumer with an unrelated source comment and pass by rehashing that altered JSON in memory; a future catalog revision needs a new source pin and review. This protects the fixed draft's references, not the scientific correctness of a lexical source link.

Run `python3 -m unittest discover -s . -p 'test_*.py'` and repeat with `PYTHONOPTIMIZE=1 python3 -O`. These tests execute no KDM, WRF or RTTOV model and require no private binary. The source and build feasibility audit is in [the report](../../../docs/NATIVE_HOST_EXECUTION_READINESS_20261113.md).
