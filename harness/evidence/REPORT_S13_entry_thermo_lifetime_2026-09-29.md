# S13: call-entry `cpm` and `xl` across outer subcycles

**S13 remains OPEN / FAIL.** The current private mp37 (SHA-256 `fc0a72d33a5e61803fea56eb9118018039c6da8b5775813032b4861a2bd66eb5`) and mp237 (`4f0103c8a8321b8e854d3500f4ae567755e41eb78746fac54519eca2686a6648`) Fortran sources calculate heat capacity `cpm(qv)` and latent coefficient `xl(t)` once before `do loop=1,loops` and reuse them through that `kdm62D` call. The public C++ and Python runtimes previously recomputed both from each subcycle's updated state. This patch caches only these two entry tensors and passes them into every microphysics one-step. Other state-dependent diagnostics, including saturation and temperature-dependent fall properties, still rebuild at their existing points. The post-freeze `work1` path already uses the carried entry `xl` with current temperature; the unused outer auxiliary `work1` is unchanged.

Its selected one-subcycle `th` and `qv` hex values match the prior code exactly. A fixed-versus-dynamic second-step check distinguishes the two coefficient lifetimes, and focused Python/C++ runtime checks verify that the cached tensors reach the executed path. The entry tensors remain in the AD graph. The old C++ one-step symbol is preserved by a compatibility overload; the C ABI and operational selector layout are unchanged.
