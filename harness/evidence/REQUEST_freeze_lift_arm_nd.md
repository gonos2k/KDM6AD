# Freeze-lift request: Arm N_d, the dry-air number transfer

## What is asked

One diagnostic arm, `--algo nmass_dry`, generated by
`make_factorial_variants.py` from `module_mp_kdm6_nmass.F` -- never hand-edited.
Two lines, the same two Arm N changed.

## Why it is a separate request

The 2026-08-21 freeze-lift for Arms N and L says, in its own text:

> `dend(i,k) = den(i,k)` (F:870), so this preserves the OPERATOR measure the
> kernel already integrates; whether the physical measure should use true dry
> density is the separate basis question `FINDING_number_mass_basis_v1` already
> records, and this request does not touch it.

This is that question, and it is asked separately rather than folded in.

## Site and change

`host/KIM-meso_v1.0/phys/module_mp_kdm6_nmass.F`, the two interface number
transfers Arm N already carries:

    dnr(i,k+1) = min(falkn(i,k+1,1)*dend(i,k+1)*delz(i,k+1)
                     /(dend(i,k)*delz(i,k))*dtcld, nrs(i,k+1,1))

becomes the same expression with the DRY layer mass:

    dend(i,k+1)/(1+qv(i,k+1))   over   dend(i,k)/(1+qv(i,k))

`qv` is already in scope on that line's own loop. No new state, no new argument,
no reordering.

## What it is predicted to do, with the number

`FINDING_moisture_gradient_basis_v1` measures the residual Arm N leaves against
the physical ledger and shows it is an identity:

    R = sum_j a_j * dz_j * ( B_{j+1} * A_j / A_{j+1} - B_j )

ratio 1.00000000 on all six rows. Substituting `A = B = rho/(1+qv)` sends every
term to exactly zero, so the acceptance criterion is not "smaller" but

    |R_dry^{N_d}| <= B_roundoff

on `g33_fixture_moisture_gradient_v1`, where Arm N currently leaves

    column 1   -6.588e-05        column 2   -7.709e-05
    column 3   -4.989e-05        (as a fraction of starting inventory)

and legacy leaves 3.788e-03, 3.618e-03, 3.492e-03. So the arm is predicted to
remove the remaining 1.7 %.

## Matched controls the arm must also pass

- **The MOIST ledger must move.** Arm N_d is not a strictly better Arm N: it
  trades closure of one measure for the other, and the moist residual it leaves
  must be reported, not assumed to stay at roundoff.
- **Uniform `qv`**: on `g33_fixture_boundary_mapping_v1`, where the two ledgers
  are proportional, Arm N_d and Arm N must agree to the last digit. That is
  what shows the arm intervenes where the MOISTURE GRADIENT is rather than
  trimming a residual wherever it finds one.
- **The mass control**, on the actual-transfer reader rather than the recovered
  one, which closes by construction.

## Scope, and what is NOT asked

- No change to the legacy default, and none to Arm N. `nmass_dry` is an
  ADDITIONAL canonical variant selected by `--algo`.
- No re-pointing of `CLAIMS.yaml`. New arms produce new bundles.
- No claim of a forecast impact. `FINDING_number_basis_gap_v1` bounds what this
  can be worth on a real atmosphere: a median 0.33 % of the legacy
  per-interface defect, p90 4.62 %, largest absolute remainder 7.08e-03 over
  2 507 544 LC05 interfaces. **The owner may reasonably decide that is too small
  to be worth a kernel variant**, and this request is written so that decision
  can be made against a number rather than a suspicion.
