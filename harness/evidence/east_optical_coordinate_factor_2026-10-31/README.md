# Offline east optical coordinate-factor verification v1

This offline replay independently derives RTTOV native BT `psi(TOTAL)`, KMA BT `phi(TOTAL)`, and `phi'(TOTAL)/psi'(TOTAL)` for the saved GG and PP K calls, 10 profiles and channels 10–16 (140 cells). It reads the archived raw K radiances and type-major ice-slot 7 HYDRO and HYDRO_DEFF K fields, and compares their independently transformed values to the archived arrays. No RTTOV or K call is made. The unchanged parent packet manifest is SHA-256 `02b4d7efb574154480bc8b5e213d21f66905d7fb501880eb9b17de013eff230a`; the verifier checks that digest and the original raw K and values hashes before parsing. A bounded independent parser consumes the verified raw bytes; it handles only the required radiance and ice-slot blocks. The KMA calibration is pinned too. Each input is read once, hashed and parsed from those same bytes. Authenticate this verifier against a trusted revision; source checks do not authenticate themselves.

Supply the original full RTTOV coefficient file separately (SHA-256 `73401691b9e5777daf0e4d8ba6d77dfc912c0d32bd8b70937886fcd91b54a7b5`). Only channels 10–16 of its `FILTER_FUNCTIONS` are selected in memory. The selected gamma values are nonzero but are not used in the native IR BT formula. The source header identifies RTTOV GKOMPSAT-2 AMI IR; it does not grant redistribution rights. The repository's `docs/RESEARCH_CANDIDATE.md` says permission has not been established, so coefficient rows are not distributed here. KMA calibration is the existing bundled table, SHA-256 `a6f830aa04e19f6982aa6ff36e832464a5b32fdcf8200211956969d5eb48325d`; only the seven relevant Planck, wavenumber and polynomial fields are read.


TOTAL is spectral radiance in mW m⁻² sr⁻¹ (cm⁻¹)⁻¹; both brightness temperatures are K, each radiance derivative has units K per radiance unit, and their ratio is dimensionless. The transformed K retains the units of native BT K per corresponding serialized optical-input unit. The expressions use `log1p` and algebraic rearrangement independently of the project transform. With nearest binary64 and a high-quality libm, the 64-epsilon bounds allow tens of rounded operations plus a few libm ulps: absolute `64 eps` for the near-unit ratio, `64 eps × 300 K` for both BT coordinates, and `64 eps × max(|saved K|, smallest normal)` plus one smallest subnormal for transformed K. They are practical cross-order replay bounds, not a formal proof for arbitrary libm or floating-point environments. They are much smaller than scientific tolerances. Native BT is compared to raw output, and KMA BT and ratios to the saved K archive. The local run observed maxima 7.772e-16 ratio, 1.137e-13 K KMA BT, 5.685e-14 K native BT, and 8.823e-16 relative transformed K.

The result remains **INCONCLUSIVE** for physical and derivative science: it checks only the coordinate map on retained raw values, not independently executed RTTOV, upstream host or QNICE derivatives, physical budgets, units, loaded libraries or a VJP. Raw captures were hashed after execution. See the parent packet README for the original run, scope and provenance limits.
